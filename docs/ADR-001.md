# ADR-001｜重写方式与总体架构

状态：已采纳（2026-09-24）。依据：用户授权在新文件夹全仓重写；`../map` 的功能盘点（`docs/inventory/` 下三份清单）；`../map/docs/refactor-guide` 中的 UX 规格、架构与调度合同；2026-09-24 在韩华海洋造船厂地图上的性能实测。

## 1. 内核移植，界面重写

**决定**：内核（`src/domain`、`geometry`、`topology`、`validation`、`compiler`）连同编辑器与适配器支撑模块（`src/editor`、`src/adapters`）从 `../map` 原样移植，带上 61 个单元测试和 9 个集成测试，并从 12 个与旧界面耦合的测试文件中拆出 5 个文件的纯内核用例（27 个）。工作台、交互、渲染从零重写到 `src/app`；支撑模块中哪些复用、哪些替换，在对应阶段说明。

**理由**：

- 兼容性要求逐字复现的细节很多：contentHash 的键序与数字格式、三版 Schema 分派、37 种命令的来源与沿革记账、编辑器分配 ID 的命名、扩展载荷的严格读取器。这些行为由约 920 个单元与集成测试（单元 812 个，集成 110 个），以及覆盖 6 个示例和 projects 下约 100 张地图的 golden 快照固定下来。从零重写内核风险最大、收益最小。
- 用户痛点集中在界面和操作上：菜单语义重叠、主要操作藏在折叠区、多入口、面板层层折叠。性能瓶颈在上一轮已按实测处理，剩余的阻塞主要是提交时的校验与渲染。

**内核后续重构**只在金标准快照（`npm run golden:check`）和测试保护下进行，按需处理以下问题：

- 拆分 `commands.ts`，把模块级单槽缓存改成显式的 prepare/commit；
- 统一 5 个同构的错误类与 12 集合常量；
- 消除 `serialization → validate → serviceConnections → semanticPatch → serialization` 这类循环依赖；
- 加载时把 0.1/0.2 的道路统一为 path，保存时按原版本写回。

**放弃的方案**：从零重写内核。兼容风险高，而且会丢失测试所固定的边界行为。

## 2. 渲染：Konva 命令式分层批量绘制（已被 ADR-002 取代）

**决定**：继续使用已安装的 Konva，但不再用 react-konva 为每个实体生成一个 React 节点。

- **分层**：底图层、静态地图层、选中与控制柄层、交互预览层。
- **静态地图**：按样式分组，用少量自定义 Shape 批量绘制 Path2D。
- **点选与吸附**：走几何内核和空间索引，不依赖 Konva 的命中图。
- **平移缩放**：只改舞台变换，停下后再按新视口重绘。

**理由**：

- 实测中 react-konva 对上千个图形逐个协调是主要开销之一。
- Konva 已经提供分层、像素比、舞台变换，没有必要自己重写这一层。

**放弃的方案**：

- WebGL/PixiJS：没有测量证据表明需要，还要新增依赖，文字标签也更复杂。
- 继续使用 react-konva：协调开销。
- 自写 Canvas2D 框架：重复 Konva 已有的能力。

## 3. 交互与操作

- **交互状态**：只有一个判别联合状态机（idle、selecting、panning、drawingRoad、drawingPolygon、editingVertices、placingPoint、measuring、previewingOperation），代替旧版十几个互相牵制的布尔开关。
- **草稿**：绑定 projectId、changeToken 和 mapContentHash。
- **操作注册表**：每个操作只定义一次，包括名称、快捷键、可用性与不可用原因、执行函数。菜单、工具条、上下文条、命令面板（Ctrl+K）和帮助面板都从它生成，消除旧版一个功能三四个入口的问题。
- **补齐旧版缺失的常用能力**：框选（左→右为完全包含，右→左为相交）、按住 Space 临时平移、Alt+点击循环选择、方向键微移、画路时显示长度和方位角。

## 4. 视觉

以 `../map/docs/refactor-guide/prototype_previews` 原型为方向：

- 浅色、低噪声；名称优先，ID 次要且可复制；
- 左栏「对象 / 图层」，右栏「属性 / 关联 / 来源」；
- 底部抽屉放「检查与修复 / 路径 / 统计」。

实现方式：用 CSS 变量定义设计令牌，控件用原生控件，不引入 UI 组件库。技术代码和 JSON 路径放进「详情」，不常驻主界面。

## 5. 持久化与文件

- **沿用旧版的存储与冲突语义**：IndexedDB 工程快照（draft、checkpoint、previousCheckpoint 加 CAS）、文件句柄关联、外部修改检测、双方备份后才允许覆盖。
- **简化用户可见的概念**：
  - 文件菜单只保留「新建、打开、保存、另存为、导出副本、最近工程」；
  - 浏览器恢复自动进行；
  - 保存状态如实报告部分成功。

## 6. 调度与仿真接口

编辑器负责静态地图、编译与发布的派生数据，以及对外部计划和运行结果的只读回放；**不做**求解与仿真。现有的 compiled-map（protocol 1.0）与 FAST01 结果协议 1.0 保留。

**待用户决定（第 5 阶段前）**：论文主线（VISTA、R1 数据）目前从数据集 CSV 建图，完全不读编辑器输出；读 map.json 的 I1/SR03 只认 0.2.0 折线。接口先服务哪个消费者，决定了两件事：

- 导出的表格列名与单位；
- 是否在地图中新增坡度、转弯半径、区域容量等字段。这需要 Schema 升级或带版本的扩展命名空间。

在消费者确定之前，不做推测性接口。

## 7. 依赖

沿用 `../map` 锁定的依赖版本，第 0 阶段没有新增依赖。react-konva 按第 2 节不再使用，在第 1 阶段随渲染层一起移除。以后新增或移除依赖须在本文件（或后续 ADR）写明决定和理由。
