设计日期：2026-09-15。在线源码核查基线：`bcf4ac4ceefedfcbbc769f694211acacb98542b8`。
仓库：`NCR7777/Shipyard-Map-Generation`。

## 1. 用一个工作流替代多轮零散加功能

用户负责：对照底图画路网、建筑和区域轮廓，目测微调道路宽度；少量修正明显错误。
软件负责：名称与ID、默认属性、直接绘图、明确吸附接路、曲线几何、引用维护、保存、轻量问题提示。
Codex负责：结合原始底图局部及全厂上下文，推测具体用途，生成可审查的语义补丁及接入建议。
外部程序负责：任务、车队、资源调度和仿真；本编辑器读取输入/输出合同并展示过程和结果。

最终工作流：

`打开并锁定底图 → 连续描路/画建筑/圈区域 → 批量补分类与运输接入 → 检查选定研究输入 → 导出 → 导入计划/过程/结果并展示`

不要让用户逐节点配转向、逐路填来源、逐建筑填写资源/服务属性。不要把本任务解释成“仅再次折叠属性面板”。

### 当前授权更新

本轮明确授权快速描图、可修改默认值、真正曲线、Codex语义补全工作流、外部调度过程/结果展示以及必要架构重构。
更新 `docs/CURRENT_SCOPE.md` 和 README 的当前范围，说明旧“止于RF01”“禁止任务回放”等条款在本轮明确范围内已被替代。历史报告保留，不反复将已授权功能判成未授权。
仍不建设：内置优化求解器、离散事件仿真引擎、实时车辆控制、3D/VR、微服务、账户系统、通用插件平台。外部计划回放不是重新开发调度算法。

## 3. 界面只保留用户当前需要的内容

顶部三种工作区：**描图 / 检查与补全 / 调度结果**。不是三套地图，只是工具和覆盖层不同。

描图工作区：
- 左侧窄工具条：选择(V)、道路(R)、弯曲(C)、建筑(B)、区域(A)、量距(M)。节点工具移到高级工具。
- 上方上下文条：道路宽度、直线/曲线、吸附、撤销/重做。无选中时属性栏可收起。
- 底图默认锁定，常用透明度和对照开关不必进入多层对话框。
- 画布不因为选中对象或新增提示而改变尺寸；问题面板默认折叠。
- 中文名称为主，ID/原始JSON/来源详情放按需展开区域。
- 工具持续有效，完成一个对象后继续画同类对象，不弹必填属性对话框。
- 界面使用米、吨、km/h、度，存储沿用 m、kg、m/s、rad。

默认视觉：真实比例道路带＋清晰细中心线；建筑/区域薄轮廓＋低透明填充；未分类与推测分类用标签/线型区分，不铺满警告图标。
只显示选中对象、当前接路目标和必要入口标记；普通几何控制点平时隐藏。不要把路线离散样本画成节点。
命中热区可以大于可见线宽，但不得将热区宽度当作物理宽度。靠近时提供吸附预览；叠放对象可循环选择。
描图使用底图对照；检查使用冲突和断点覆盖；结果使用清洁矢量底图加路线、车辆与热图，底图可关闭。
不增加无必要的3D透视、拟物建筑、密集图表、连续发光动画和大标题栏。

## 4. 新建对象默认可用，不再逐项填表

### 4.1 项目级快速描图配置

提供开箱即用的 `quick_trace_v1`。下面数值是产品交互/模拟默认值，不是船厂实测或行业标准。

| 项目 | 初始建议 | 修改方式 |
|---|---|---|
| 新道路宽度 | 12 m；或上一次主动设为新建默认的宽度 | 上方一个数值框、宽度侧柄，支持多选改宽 |
| 新道路方向 | 双向，标为绘图配置的设计假设 | 画布箭头切单向/反向；原图不补写 |
| 新普通路口 | 在明确接路手势下，按配置声明方向兼容的非掉头转向 | 批量编辑或路口小面板；旧禁转保留 |
| 速度 | 制图时不要求；地图保持原值/未知 | 时间分析场景可显式选用5 km/h研究假设，不能假称测量 |
| 限高/承载 | 未知 | 需要对应车型约束时再补，不默认为无限 |
| 建筑 | 通用建筑、用途待推测 | Codex补分类；用户可覆盖 |
| 区域 | 通用区域、用途待推测 | Codex补分类；不默认区域内处处可开车 |
| 名称 | 道路001、建筑001、区域001 | 非必填；唯一性靠ID，不靠名字 |
| 高程 | 继承当前本地绘图平面 | 不等于测得海拔；不自动跨层连接 |
| 资源/库存 | 暂无、不推算 | 调度准备时按研究所需配置 |

现有道路“用于随后新建道路”的功能应继续用，但成为项目内可恢复设置，不复制旧来源为新现场事实。
默认配置仅影响之后新建的对象。修改默认宽度不能悄悄改全厂旧道路；需要全厂改动时使用显式批量操作。
默认来源按一次配置版本复用一个 source，别为每次同值输入生成无意义重复来源。已导入数据中未编辑字段原值保留。
默认值创建后落入权威map；偏好配置另存EditorState。地图导出时足以重现结果，不能依赖某台电脑的当前默认值才能解释方向/宽度。

### 4.2 通用类别的最小表示

优选随曲线版本 `0.3.0` 给 `Facility.kind` 增加 `building`，给 `Zone.kind` 增加 `unclassified`。只增加确实需要的通用类别，不重建完整业务分类体系。
建筑始终先作为一个设施保存；区域始终先作为一个区域保存。不要复制同一轮廓到两套字典。Codex若认为需要改变实体大类，给出专门建议，不自动跨集合迁移ID和所有权。
具体用途可在已有kind或小型已声明注释结构中补充；不能把影响通行的字段藏在不受支持的metadata中。

## 5. 道路怎样画才快

### 5.1 直线和折线

选道路工具后，点起点、点终点，Enter/双击结束；中途多次点击形成几何折角。
起终点自动创建或复用网络节点，用户不先画节点。没有分支、属性分段或服务作用的中途折角，只是geometry的锚点，不是网络节点。
落在已有节点/道路时预览“接入此路”。在快速描图模式，用户明确接受的吸附落点本身就是接路授权，完成一次原子拆路/复用节点/引用维护，不逐步弹窗。
已有未支持依赖或新接路会改已有禁转时，才使用一次集中预览。不同声明高程、跨水结构不明、路网不清楚的交叉不自动接。

普通穿越另有规则：
- 新描道路与新描道路在当前平面交叉，可按已启用的“本项目新建平交相连”配置生成路口；画布预览新节点和连通图标，Alt可明确本次不连接。
- 配置只对本次新建/明确接受交点生效，不扫描并改写全部旧图。
- 导入旧图的交叉、现有禁转、层级证据不明的对象，使用集中确认而非猜测。
- 默认非掉头转向是明确模拟假设，不声称知道现场交通管理。

这是比“所有交点必弹框”更快、又比“全图近点自动合并”更可控的方案。

### 5.2 曲线的用户操作

常用入口只有一个“弯曲”：选一条直段，拖中点鼓起，形成曲线；或者切曲线工具，起点—终点—弯曲位置三次点击。
普通用户不填Bezier控制点和t参数。选中曲线后才显示端点、弯曲柄；高级编辑可显示两个切向柄。
支持直线→曲线→直线连续绘制。接续时显示平滑/折角，平滑约束仅在本次操作中维护，不建设通用约束求解器。
拐角“圆滑”是可选几何编辑，不能自动将有分支的路口删掉。三次Bezier近似圆弧不等于精确圆弧；首期不增加NURBS/样条/圆弧四套持久化类型。

### 5.3 道路宽度要按米显示，且能拖边

`屏幕物理带宽 = widthM × 当前相机px/m`。只在有效地理尺度/校准基础上说按米显示；这不自动证明实测净宽。
选中道路时，在合适位置显示垂直于局部切线的宽度侧柄，中心线固定。拖柄即时预览道路两侧、最后一次提交；可输入12→16 m，支持0.5 m步进或自由数值。
曲线使用同一宽度口径，不能曲线粗细固定为屏幕像素。缩放视窗不改变米制宽度。
第一版每条拓扑路段一个宽度即可。局部变宽通过用户“此处开始变宽”操作自动拆段和继承引用；先不引入可变宽度曲面编辑器。
真实比例道路带可在总览上很细；另用细中心线保证可见，但不要把放大的交互辅助线冒充物理带。
不通过缩小建筑或极端缩窄道路消除冲突。重叠先提示并定位，制图可保存需复核状态，发布具体研究输入时再处理相应问题。

## 6. 建筑与区域的最快标注

建筑默认矩形：拖两个对角点。斜厂房支持“三点矩形”：沿一边点两点，再点第三点确定深度，自动保持四直角；也可在当前局部朝向下连续画同方向厂房。
区域默认多边形：沿边点击，Enter/双击结束；Shift约束水平/垂直或当前局部主轴。支持插入/删除形状顶点，不把它们变成路网节点。
复制连续相似建筑支持Ctrl+D/Alt拖动并给出相同尺寸，不强迫逐个分类。
默认粗类够用；不要要求先辨认钢加、涂装、总组、仓储等业务用途。

早期描图时边界默认独立：未创建服务/内部路/储位，不提前构造这些依赖。
后期已有关系：拖主体移动明确私有内容，公共路网固定；拖角改轮廓不缩放内部路和储位。沿用UX02和近期入口脱离共享节点修复，不把所有权判断改成“几何落在里面”。
地图始终可通过同一权威几何编辑；不能有“描图简版”与“调度完整版”两套互相失配的编辑几何。

## 7. 曲线必须贯通计算链

实施合同见 `CURVES_AND_EXCHANGE.md`。必须同时更新：
1. JSON Schema/类型/升级、权威路径读取；
2. 渲染/范围/命中/宽度侧柄；
3. 曲线长度、最近点、按里程定位、切向；
4. 拆路/连接/合并、正反向引用重映射；
5. 碰撞候选、道路带与建筑/区域关系；
6. 路由/编译、外部读取及回放。

禁止只给Konva.Line加tension然后继续按原折线算长度，也禁止为曲线每1m创建一个网络节点。
渲染与计算均由同一个几何定义派生；计算采样精度不跟随视窗缩放。曲线可通与某个SPMT/货物实际能转过是不同结论。

## 8. Codex怎么补分类，不增加用户填表

先做文件工作流，不建设在线AI后台，不要求额外API key。按钮应命名“导出Codex补标包”，不是虚假的“自动识别已完成”。
包中包括当前map、默认配置与来源摘要、原始/校准底图、总览、按对象裁剪的无覆盖原图和带ID轮廓对照图、像素变换和待分类对象清单。裁图保留足够周围道路/厂房上下文；不要只给模型彩色轮廓截图。
Codex输出 `semantic_patch.json`，包含baseMapContentHash、实体、字段、旧值/新值、证据与推测等级。补丁不是直接重新生成整张map。

自动化边界：
- 常见建筑/区域用途可推测并批量应用；显示“推测”，允许用户一键改回。等级高/中/低是证据分级，不虚构校准概率。
- 低把握时保留通用类别，不强行给每个对象分配具体工艺。
- 不覆盖用户明确修改并锁定的字段；不改变手绘几何、宽度、坐标框架、ID、转向和资源。
- 不从影像猜承载、净高、装卸时长、真实产能和实时库存。不得将普通工业影像猜成具体官方资产台账。
- 分类变化如需要改变通行/障碍语义，另列其影响，由模拟配置或用户明确接受；不能偷偷使原本可通区域禁止或反过来。
- basehash过期直接提示重新导出/生成；不建立复杂的自动三路语义合并。
- 高/中把握语义可按用户本项目预授权一次批量应用；低把握集中列出，别把每栋楼变成确认弹窗。

来源注释保留“人工描形 / 默认设计 / 模型推测 / 人工修改”的分工；不要因为批量接受就把inferred改成surveyed。

## 9. 从大块轮廓到调度输入，不要求用户手工画每个服务点

“准备运输分析”按选择的研究级别做检查，而不是要求一次填满全部字段。

**空间标注级**：几何、粗类、宽度、来源及框架；未分类/无装卸点可以保存。
**网络路由级**：选定运输目标、道路方向/转向、实际连续接入和路径；可使用用户明确接受的研究假设。
**时序调度级**：外部场景提供任务、车辆、速度、日历、资源容量、服务时长与约束。

软件可以对用户标为运输目标的建筑/区域生成“接入建议”：候选入口及短接入线必须在可辨陆域，不跨楼/水；可一次接受一批清楚候选。不强迫用户手工填写accessPointId/nodeId。
没有门洞证据时生成明确的边界交接代理，只代表研究模型假设，不声称真实厂门。内部细路、储位、岸吊等不凭空创建。
仅为本研究使用的目标补接入，不给每座辅助建筑机械建货运入口。未完成目标必须在交接报告中点名，不能悄悄跳过后声称全部可用。

已有 `node_proxy`/`explicit_internal` 复用：代理的内部转运算入服务时间或排除必须有场景说明；显式模式按声明内部道路到达，不能从入口瞬移。
推荐先把研究收敛到节点/边级运输网络；更精细车辆扫掠和场内储位物流留给明确有需求的外部分析。

## 10. 过程展示与结果展示纳入本轮产品，不只留空接口

首期消费本地 `plan.json`、`events.jsonl` 和 `summary.json`。通过一个格式化消费者生成覆盖层，未来实时流复用相同消息模型；不先建设WebSocket后端。

必要展示：播放/暂停、拖时间、倍率、车辆和任务筛选、当前路线、等待/运输/装卸状态、任务时间条和关键结果表。
关键结果可包含完工时间、总行驶距离、等待时间、迟交、资源利用率；输入必须提供口径/单位/时间范围。缺数据就显示未提供，不用地图面积或槽位数推算产能。
比较两方案时必须匹配地图、场景和指标口径；不同任务集合或时域不能不加说明并列评分。
车辆位置按曲线弧长定位，不能简单线性推进Bezier参数t造成速度忽快忽慢。反向行驶yaw随行驶方向，等待阶段不继续移动。
计划中只有离开/到达时刻时，可采用标注为“区间匀速插值”的显示，不声称还原真实速度。无连续运动证据的跨度不跨水直线插值。
没有外部求解器时提供命名为synthetic的固定示例用于接入测试，不能将它的效率指标当作优化结果。

## 11. 简洁实现：保留五条底线，其余尽量减少

只保留必要底线：
1. 普通编辑不改coordinateFrame，缩放视窗不改米制几何。
2. 用户数据不丢；单动作单事务，失败回滚，保存失败如实显示。
3. 拆并/接路维护引用和明确许可，不清空依赖换取成功。
4. 默认、推测、实测分开；未知不会自动变成无限制。
5. 外部补丁和结果绑定输入版本；旧结果不冒充当前图结果。

应该删减/合并的成本：
- 每次普通操作都弹来源/依赖/未完成确认；改为自动记录和非模态状态，只有破坏性或真实歧义需确认。
- 鼠标移动每帧全图Schema验证、完整hash/深克隆、全量规划扫描；预览不提交，提交检查必要域，最终发布检查全图。
- UI、画布、工具栏各一套相同规则；全部调用同一个领域动作。
- 每批新建多个“状态管理器/权限系统/审计总线”；一个工具会话、一个事务入口、一个保存控制器即可。
- 为数量或隐藏状态非空而禁止全部编辑；按具体已理解的依赖处理。未知且可能影响全图的行为仍保留必要保护。
- 无限细化图层或强制每节点独占资源；没有研究需要就不建。
- 只为压缩行数写难懂代码；不做通用几何编辑平台，不自制第三套全局状态框架。

新模块建议（优先融入现有目录，而非全部机械创建）：
`geometry/roadPath.ts`（line+cubic），`editor/drawingSession.ts`（手势草稿），`domain/drawingDefaults.ts`，`compiler/routing.ts`，`adapters/semanticPatch.ts`，`adapters/results.ts`。
