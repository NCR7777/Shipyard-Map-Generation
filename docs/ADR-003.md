# ADR-003｜离线底图预处理脚本（Python）随工具保留

状态：已采纳（2026-09-25，P4c）。

## 决定

- 把旧版的 `BG01_prepare_raster.py` 与它的测试移入本工具（`scripts/`、`tests/python/`），内容不改。
- 它在浏览器之外运行：有校准文件或投影参数时，把影像（PNG/JPEG/TIFF；GeoTIFF 自动读取需 rasterio）按 EXIF 摆正、按像素重投影到地图本地米制坐标、缩到浏览器能导入的尺寸，输出图片、`BG01_background_calibration_v1` 校准 JSON 与回执。本工具「添加底图」时同时选图片和这份校准 JSON 即可对齐。它不做没有坐标的单纯缩小。输入上限 1 亿像素、输出最长边上限 4096：整厂卫星 GeoTIFF 多数超出，用 `prepare_tiffs.py`（见下）。
- 新增的是 Python 依赖，不是前端依赖：NumPy、Pillow、pyproj；GeoTIFF 另需 rasterio（可选）。npm 依赖不变，浏览器包不受影响。验证过的版本：Python 3.11.15、NumPy 2.4.4、Pillow 12.2.0、pyproj 3.7.2（PROJ 9.5.1）、Node 22.18.0、tsx 4.23.13。tsx 是开发依赖，`npm ci` 会装上；只装生产依赖时脚本的内核复核跑不起来。
- 运行环境用 conda 环境 `paper`：旧版一直在这里运行，本机只有它装有 pyproj。`paper01`（本仓库 Python 的首选环境）没有 pyproj；用户的 D4 实验在 `paper01` 满载运行时，不向其中安装，以免依赖解析改动正在运行的实验所用的包。
- 脚本复核结果时调用本工具自己的内核（`src/domain/load.ts`、`src/adapters/backgroundCalibration.ts`、`src/adapters/rasterFiles.ts`，经 Node 与 tsx），与浏览器导入用同一套判定。这份接口由单元测试 `tests/unit/P4c_bg01CoreContract.test.ts` 守着：它取出脚本里的那段 TypeScript 程序原样运行，核对脚本读取的每个字段。以后改这三个文件（例如 P3d2 改校准），门禁里的单元测试会发现接口与字段的变化；改动校准的语义（例如控制点的含义、变换的计算）时，仍要跑 Python 测试。

## 依据

- 浏览器端只接受 PNG/JPEG/WebP、32 MiB 与 2400 万像素以内的图片，不做投影变换；遇到 EPSG:3857→UTM 这类非线性链时返回 `preprocess_required`。本工具的仓库里能把这类影像变成可导入格式的只有这个脚本（整厂 GeoTIFF 由仓库外的 `prepare_tiffs.py` 处理）。
- `../map` 迟早停用；脚本留在那里，停用后就无从预处理。
- 用户要求「旧版脚本……有用就移植」（2026-09-25）。

## 放弃的方案

- **在浏览器里做重投影**：要把 PROJ 编成 WebAssembly 或引入大体积的投影库，主包显著变大；逐像素重投影大图也不适合放在编辑器的主线程。按 Ponytail 原则，离线脚本足够。（2026-09-25 用户问「图像预处理可否集成在网页工具中」，2026-09-26 确认做 P3d3：在 Web Worker 中按需加载 geotiff.js 与 proj4js 重新评估；这一条维持到 P3d3 原型通过、另立 ADR 取代为止。）
- **改写成 Node 脚本**：可以用 proj4js 与 geotiff.js 实现，但要新增依赖，并重新验证逐像素重投影、EXIF 与 nodata 的处理；现成的 Python 实现已有测试、真实 CIMC 与真实威海 GeoTIFF 的运行记录，重写没有收益。
- **同时移入 `projects/TIF_可导入底图_20260915/_processing/prepare_tiffs.py`**：九厂 TIF 底图实际由它生成（rasterio/GDAL），整厂影像也只有它处理得了，但它是那一批交付的数据管线，输入输出写在交付目录里，保持原处；用户文档说明两者的分工。它依赖单独安装的 rasterio 1.4.4 / GDAL 3.10.3（TIF-tools），用户 2026-09-25 决定把它从 `../map/.cache/TIF-tools` 移到本工具的 `.tools/TIF-tools`（不纳入 git），`../map` 停用时不受影响。

## 已知限制

- 真实 GeoTIFF：P4c 审查时把 TIF-tools 加到 `sys.path` 末尾（不安装），跑通一张威海 GeoTIFF，输出与交付的底图对齐；没有写成自动测试（依赖本机的 TIF-tools 与原始影像）。
- 输出最长边默认 2048、上限 4096 像素，不切瓦片、不建金字塔；超过约 1.79 亿像素的源图打印 Python 回溯，没有 BG 错误码（旧版如此）。
