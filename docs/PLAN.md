## P1B 底图显示（2026-09-24 用户确认插入，排在 P2 之前；已完成，报告见 reports/P1B.md）

描图需要底图，没有底图时 P2 的绘制无法在真实场景中验证，所以把底图的显示提前；校准、拖动调整、替换、重新关联仍在 P3。

- **内容**：
  - 与 `../map` 隔离：开发与预览固定使用 5180 端口，浏览器数据库名为 `shipyard-map-studio`，不与旧工具共用同一源和工程库；
  - 打开：文件对话框与拖放都可以一次选多个文件（地图 JSON、zip 包、图片）。zip 支持未压缩与 deflate（浏览器原生解压）；包内只有一张地图时直接打开，有多张时让用户选择；
  - 图片按 SHA-256 匹配地图中声明的图片资源，并校验格式与像素尺寸。匹配成功后存入本工具的浏览器数据库，下次打开同一地图自动载入；不匹配时说明原因，替换属于 P3；
  - 显示：底图画在矢量下方，按 `imageToWorld` 仿射绘制；显示底图时网格淡化；
  - 图层页「底图」：每层显示状态（就绪、缺图、载入中、不支持、错误）、显示开关、透明度、适应底图、选择图片；影像对照模式淡化填充，道路 ×0.25，建筑与区域 ×24/53，与旧版一致；
  - 命令：适应底图、显示或隐藏全部底图、选择底图图片。
- **不含**：锁定（只有能调整底图时才有意义，随 P3 一起做）；底图偏好的持久化（P4）；文件夹拖放（需要时再加）。
- **验收**：
  - e2e：打开 JSON 再加图片后底图可见（按已知世界点检查像素颜色）；SHA 不符的图片被拒绝并给出原因；zip 包中的地图与图片一起打开；刷新后从浏览器数据库自动载入；隐藏与透明度生效；不支持的图层给出原因；
  - 性能：在韩华 TIF 底图（4105×4351）下，与 `../map` 加载同一底图时背靠背比较平移与缩放，不劣于旧版。

## P3 业务对象与拓扑

**分段（2026-09-25 定，按描图的工作顺序排列；各段独立审查、单独提交）**：

- **P3d 底图导入与校准**（先做）：现在只能显示地图里已记录的底图，不能从一张新图片开始描图；这是用本工具新建描图的前提。内容：导入图片为底图、比例与坐标校准、拖动与缩放调整、锁定、重新关联与替换。旧版（`../map`）没有交互校准，只能导入离线脚本生成的校准 JSON；新建描图时没有校准 JSON，只能靠猜测数值定比例，所以交互校准是本段新增的能力。再分两段：
  - **P3d1 导入、调整与定比例**：
    - 添加底图（文件菜单、图层页、空白地图提示），可同时选旧版格式的校准 JSON（`BG01_background_calibration_v1`），一次添加是一个撤销步骤；
    - 未校准时的初始位置：有矢量或其他底图时覆盖其范围，空白地图按 1 米/像素、左下角在原点；添加后直接进入调整；
    - 调整模式：只在明确进入后可动（这就是「锁定」：平时点不中、拖不动底图）。画布上拖动移动、拉角缩放（默认保持宽高比，Shift 临时取消）、旋转柄（Shift 按 15° 取整）；方向键 0.1 m、Shift 1 m，连续微调合为一步且在地图里只留一次改动；数值字段（左上角 X/Y、宽、高、角度、米/像素）逐字段提交，未改的字段不动；
    - 量距定比例：在图上点两点、输入实际长度，以第一点为不动点整体缩放；
    - 替换图片（保持原宽度和位置；宽高比相同则保持原范围，一个撤销步骤）、删除底图（可撤销，图片字节保留）、重新关联（P1B 已有）；
    - 修正 P1B 缺口：图层表中「底图」类型的隐藏与锁定对图片生效。
  - **P3d2 控制点配准与校准文件的坐标框架**：
    - 图上点与地图已知点成对（吸附节点），≥2 点相似变换、≥3 点仿射，残差与检查点。内核的 `updateBackgroundTransform` 会把配准方式记为 manual 并保留旧控制点，记录方式需先定；
    - 新建地图时可采用校准文件的坐标框架（含地理锚点）：新建地图没有锚点，带锚点的校准文件现在用不上（P3d1 审查 I1）；
    - 开始前须裁决的内核问题：每次底图改动追加一条沿革来源，描述含全部 `sourceRefs`，地图按平方增长，真实韩华地图约 575 次改动触及 10 MiB（P3d1 审查 B1；微调已在界面层合并）。
  - **P3d3 浏览器内影像预处理**（用户 2026-09-25 问「图像预处理可否集成在网页工具中」，2026-09-26 确认「继续做」；先做原型。排在 P3d2 之后是排期选择，不是硬依赖：韩华等已有地理锚点的地图上原型用不着 P3d2；真正的前提是 P3d2 开工前要定的「内核沿革做法」，因为底图导入会追加沿革来源；新建地图采用校准文件坐标框架也在 P3d2 做。它推翻 ADR-003「放弃的方案」中的「在浏览器里做重投影」，原型通过后另立 ADR 取代那一条）：
    - 目标：在「添加底图」里直接选 GeoTIFF（或有校准的大图），在浏览器里读出坐标、按像素重投影到地图本地坐标、缩到可导入的尺寸，再走现有的导入流程；不再需要 Python 与 `prepare_tiffs.py`，离线脚本保留作后备。
    - 九厂源图的实测条件：3 波段 8 位、EPSG:3857、LZW 压缩、按条带存储、没有内部金字塔，1300 万至 2.55 亿像素、37–285 MiB。要缩小就必须把整张图解码一遍。
    - 做法分两级（按输出像素反算要随机访问跨条带的源像素，不能与逐条带解码直接合成一步）：
      1. Web Worker 中用 geotiff.js 逐条带解码，在源坐标系里缩采样成一张带余量的中间图（不把整图放进内存）；
      2. proj4js 对输出的每个像素做 EPSG:3857 → 地图锚点坐标系的反算，从中间图取样；OffscreenCanvas 编码输出。
      两个库只在用到时加载，主包不变。新增依赖写 ADR。
    - 先做原型：在最大的恒力（2.55 亿像素）与韩华上测耗时与内存峰值（至少同时有中间图与输出图），结果与 `prepare_tiffs.py` 的交付底图比对（平均灰度误差、相关系数、平移，另加锐度或边缘指标，看两级重采样造成的模糊）。原型不达标（内存溢出或耗时过长）时，这类特大影像仍用离线脚本，浏览器只处理中小影像。九厂源图的像素与文件大小由执行者用 TIF-tools 读元数据得到，审查者未核对（源图不在交付目录中）。
