## 交付性质

这是供 Codex 实施的产品、交互、架构、数据和验收指导，不是已经合入的补丁。
本轮通过 GitHub 连接读取了固定提交的核心命令、拓扑保护、界面组件、样式、渲染交互、会话、序列化、适配合同、验证及阶段报告，并检索此前需求文件。审查以核心链路为重点，不声称逐行审计了全部文件。
直接下载仓库源码副本时遇到 DNS 解析失败，因此没有安装该项目依赖、启动原编辑器、执行原项目测试或计时基准。交付包中的 HTML 是交互布局原型，不是重构后的编辑器；其检查不代替原项目验收。

## 本次产品决定

重构为“本地优先、面向船厂运输研究的二维空间与运输语义编辑器”。
保留现有 React/TypeScript/Vite/Konva、YardMap、纯核心、事务、来源、撤销及保存链。重整交互与代码职责，补齐已知地图实体的操作和外部系统交接，不推倒重写。

用户本次授权的是全项目完善及未来调度接入。历史文档中的“只做某个小批次”不能阻止本计划提出下一阶段；但这不等于授权在编辑器内建设优化求解器、离散事件仿真、真实派工、三维或 VR 系统。新增的是可执行、可验证的交接能力，而非调度平台。

## 阅读与执行顺序

1. 阅读 `01_AUDIT_REQUIREMENTS.md`，确认当前已实现事项，避免重复修复 GA01/TE01。
2. 阅读 `02_UX_SPEC.md`，打开 `UI_BLUEPRINT.html`。原型用于讨论信息层级，不能复制为第二套编辑器。
3. 阅读 `03_ARCHITECTURE.md`、`04_FEATURES.md`，明确命令边界和功能闭环。
4. 阅读 `05_FILES_IMAGERY.md`、`06_SCHEDULING_CONTRACT.md`，固定文件和接入合同。
5. 按 `07_CODEX_PLAN_TESTS.md` 的 RF00–RF07 逐阶段实施；`CODEX_START_PROMPT.md` 可直接交给 Codex。

完整合并版为 `FULL_GUIDE.md`。源文件分章只是便于分阶段阅读；实施时不再为每个小任务建立一套新制度或重复维护多份状态表。

## 必须保持的结果

- 现有 0.1.0/0.2.0 地图能按原合同读取；界面重构不自动迁移、不重新编号、不改地理锚点。
- 九厂 V01 与仓库冻结的九厂 V02 共十八份目标资料分别验收；是否取得原件、是否命中冻结 SHA 必须实录。
- 普通用户可以完成一条工作链：打开 → 叠加参考图 → 选中并精修 → 明确接路 → 配置服务/储位/资源 → 检查 → 保存 → 发布外部研究输入。
- “暂不支持”不能成为已知核心实体永远不能修改的借口；需要实现有限、明确的依赖维护。未知行为扩展仍必须保护。
- 发布输入、草稿合法、路径候选、现场安全是四个不同结论，不混用。

## 使用方式

把本目录复制到本地仓库的 `docs/refactor-guide/`，或保留为仓库外的只读任务资料。让 Codex 从本地最新 HEAD 开工，先比较本审查基线后的差异，不回退代码。不要上传私有原始地图/卫星影像到公开仓库。

本轮没有向 GitHub 提交、推送或修改代码，也没有修改用户的地图原件。

## 布局原型与截图

`UI_BLUEPRINT.html` 是自包含HTML布局原型，可用于讨论信息层级。可以试用对象选择、搜索、图层显隐、面板和检查抽屉切换；几何字段只读，保存、发布等按钮会明确说明尚未实现业务功能，不会写用户文件。

`prototype_previews/` 包含1920×1080、1366×768、1093×614及窄视口截图。`checks/prototype_check.json` 记录19项原型检查；全部通过，仅证明本轮原型的指定交互。托管浏览器拒绝file://导航，因此检查通过内存HTML加载执行，没有绕过策略，也不把它写为本机双击验收。窄视口检查不是实际浏览器200%缩放审核。

本原型不是必须逐像素复制的最终界面。Codex 应将布局要求落实到现有应用，保留既有命令和数据保护，而不是复制本HTML另建编辑器。
