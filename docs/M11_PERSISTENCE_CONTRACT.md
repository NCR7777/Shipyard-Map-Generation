# M1.1 浏览器工程持久化契约

本文件描述当前实现。自动化测试结果以本轮实际运行的阶段报告为准；本文件不把故障注入测试称为机器实际耗尽配额，也不把接口存在称为原生文件授权验收通过。

## 数据与身份

地图继续使用既有 `YardMap`、Schema 和稳定序列化。浏览器工程没有另一份 Canvas 专用语义模型。工程中的快照保存完整规范化 `mapJson` 与 `contentHash`，恢复经过 `loadMap` 的解析、结构/语义校验、摘要和场景派生流程；未支持实体及扩展保留既有能力门禁。

`projectId` 是浏览器保存槽位的身份，独立于地图的 `mapId`。导入 JSON 或另存恢复副本可产生新的 `projectId`，同时保持地图原有 `mapId`、实体 ID 和引用不变。它表示保存副本，不冒充新的布局变体。恢复副本在最近项目记录名称中添加“恢复副本”，不改写地图名称和来源声明。

IndexedDB 数据库默认名为 `shipyard-map-projects`，数据库版本为 `1`。存储对象如下：

| 对象库 | 主键 | 内容 |
| --- | --- | --- |
| `projects` | `projectId` | `formatVersion: 1`、项目名称、独立 `storageVersion`、时间和地图快照 |
| `editorStates` | `projectId` | `camera` 和六项稳定 `drawing` 配置；不写进 `map.json` |
| `metadata` | `lastProjectId` | 新标签页可用的最近打开工程后备值 |

底图二进制尚未加入本阶段存储。未来必须采用独立对象库和显式资源提交/恢复协议，不将图片 Base64、文件句柄或 Blob URL 塞进地图 JSON。本阶段不声称已解决图像与地图的事务一致性。ZIP 工程包仍属于后续 M2B。

## 稳定绘图配置

`EditorState` 保存完整 `{ camera, drawing }`。`drawing` 的字段和默认值如下：

| 字段 | 合法值 / 默认值 |
| --- | --- |
| `snapGrid` | 数值 `0 / 1 / 5 / 10` m；`0` 关闭（默认） |
| `snapNodes` | 布尔值，默认 `false` |
| `facilityKind` | 现有设施类型枚举，默认 `workshop` |
| `zoneKind` | 现有区域类型枚举，默认 `work` |
| `facilityMovePolicy`、`zoneMovePolicy` | `boundaryOnly`（默认）或 `withAssociatedNodes` |

旧记录只有 `camera` 或缺少某些配置字段时补默认值；明确的 `false`、`0` 保留。未知字段、空值、非法布尔/枚举/数值拒绝。配置损坏产生 `EDITOR_STATE_RECOVERY_FAILED` 提示，仍恢复有效地图；随后使用默认编辑状态。地图 Schema 和数据库版本均不变。

配置和视窗变化共用 600ms 防抖，所有入口提交完整编辑状态快照；仅改配置触发的自动保存不改变地图 JSON、revision、contentHash、storageVersion 或撤销历史。“保存工程”/Ctrl+S 不等待防抖，先保存调用时的配置，再保存地图确认点；期间出现的新编辑仍显示待保存。恢复必须等 React 中的地图与编辑状态匹配目标后才开放写入。写入、回执和错误绑定具体工程及切换序号，工程切换前刷新当前完整状态。

“恢复绘图默认配置”只重置六项配置，保留视窗和地图。刷新回到选择工具，矩形重新自动识别；不保存自由多边形模式、拖动预览、弹窗、删除确认、未完成绘图或未应用表单。浏览器另存恢复副本携带当前配置；外部 JSON 的独立备份不混入当前工程配置。所有编辑状态仍只存本地 `editorStates`，没有新增配置数据库或设置框架。

## 快照与确认点

每条工程记录保留三类快照，快照均含完整 `mapJson`、`contentHash` 和 `savedAt`：

- `draft`：最近一次成功自动草稿或显式保存。
- `checkpoint`：最近一次显式“保存工程”确认的地图；自动草稿不会替换它。
- `previousCheckpoint`：此前一次显式保存；不构成无限版本历史。

显式保存原子更新 `draft` 和 `checkpoint`，同时保留上一 `checkpoint`。草稿保存只替换 `draft`。地图快照写入失败不更新控制器确认基线，不破坏此前成功记录。

IndexedDB `put` 请求成功不等于保存确认。适配器只在包含比较和写入的读写事务触发 `oncomplete` 后返回成功。浏览器存储确认不是永久备份或跨设备同步承诺，也不承诺操作系统突然断电时的物理落盘保证。

保存调用立即捕获地图 A，再进入同标签页串行队列。返回回执的项目 ID、摘要和版本均属于 A；保存期间产生的编辑 B 必须与回执摘要重新比较，不能因 A 完成就显示 B 已保存。切换项目后，旧项目的完成回执不更新新项目确认基线；未开始执行的旧项目排队保存拒绝为 `PROJECT_CHANGED`。

地图已提交而“最近工程”、视窗或绘图配置记录单独写入失败时，保留地图成功基线，并报告 `PROJECT_AUX_SAVE_FAILED`。它与地图事务整体失败有区别。

`EditorSession.acknowledgedHash` 只服务编辑会话的导入/持久化确认。浏览器工程控制器分别维护草稿和显式保存摘要；原生文件控制器另有文件目标确认基线；JSON 导出仅发起下载，不更新这些保存目标。

## 启动、恢复与工程切换

初始化是幂等的共享异步操作，兼容 React StrictMode 的重复挂载。初始化未完成时，`save` 拒绝为 `PROJECT_NOT_READY`，禁止初始空地图覆盖旧工程。初始化失败可以重试；源码不会自动清空损坏数据库。

每个标签页优先读取自身 `sessionStorage['shipyard.activeProjectId']`，以免其他标签页打开项目后令当前标签页刷新时跳到另一地图。首选工程确实不存在时产生警告并尝试全局最近项目；首选记录存在但所有快照均损坏时明确报错，不悄悄改成另一个项目。浏览器关闭或禁用 sessionStorage 时，无法保证该标签页偏好继续存在，新页面按全局最近项目恢复；地图存储 CAS 保护仍独立生效。

恢复按 `draft`、`checkpoint`、`previousCheckpoint` 顺序选取有效快照，并检查正文摘要一致。损坏草稿可回退到有效显式快照，提供警告，保留原记录，不立即自动修补。恢复基线使用实际成功读取的快照摘要，避免无用户编辑时将回退内容自动覆盖原草稿。

控制器选择已改变但界面恢复回调抛错时，协调 hook 立即隔离存储：暂停自动草稿、编辑状态保存、显式保存、恢复副本和项目导航，防止仍显示的旧地图写入新槽位。重试按控制器当前 active projectId 重新读取及校验；尚未落盘的候选通过保留的临时候选重新校验，不能复用初始化缓存跳回旧工程。“仅内存继续”允许绘图与导出，但保持浏览器保存禁用。

新建工程只创建内存上下文，首次地图提交成功前不写入孤立编辑状态记录。视窗与绘图配置预存在控制器，地图首次保存完成后再存储。恢复后的撤销/重做历史、未应用表单输入和草稿中的未完成道路不保存；它们不是已提交地图内容。

UI 切换、新建和导入前保存当前已提交版本。失败或取消保持旧编辑上下文；导入新项目使用不同保存槽位，原工程记录仍保留。发生跨标签页冲突时，可先调用 `backup(projectId, map)` 写入独立恢复副本，再打开副本。`backup` 本身不改变当前项目、最近打开指针或源地图，写入失败仍停留在原项目。

## 并发与错误

`revision` 是地图修订字段，可能因撤销或手工 JSON 编辑而回退/不变，不能作为数据库锁。每次成功保存另行递增 `storageVersion`。适配器在同一个 `projects` 读写事务中读取当前版本、比较预期版本并写入新版本；两个标签页不会采用无提示的最后写入覆盖。

版本不符返回 `PROJECT_CONFLICT`，保持当前内存编辑和数据库中另一标签页已保存版本。重新获得窗口焦点时可用 `checkExternalVersion()` 检测变更，它只报告冲突，不读取并替换当前地图。视窗与绘图配置使用独立对象库，不改变地图 `storageVersion` 或地图摘要；同工程编辑状态采用最后成功写入值，不属于地图语义并发编辑。

主要错误包括：

| 错误代码 | 行为 |
| --- | --- |
| `PROJECT_NOT_READY` | 恢复尚未完成，拒绝保存 |
| `PROJECT_CONFLICT` | CAS 版本冲突，不覆盖另一标签页 |
| `PROJECT_STORAGE_QUOTA` | 配额失败，不更新地图保存确认 |
| `PROJECT_STORAGE_UNAVAILABLE` | 存储不可用，可继续内存编辑和 JSON 导出 |
| `PROJECT_NO_VALID_SNAPSHOT` | 没有有效恢复快照，不写空地图 |
| `PROJECT_HASH_MISMATCH` | 快照正文与摘要不一致，尝试同记录有效后备 |
| `EDITOR_STATE_INVALID` | 视窗或绘图配置非法；不会将它混入地图 |
| `EDITOR_STATE_RECOVERY_FAILED` | 编辑状态无法恢复，提示并使用默认值，有效地图保留 |
| `EDITOR_STATE_SAVE_FAILED` | 编辑状态写入失败，保留先前记录与当前内存地图，不确认配置成功 |
| `PROJECT_AUX_SAVE_FAILED` | 地图已提交，最近工程、视窗或绘图配置附属记录未保存 |

项目列表按最近地图保存时间排序。存储按浏览器配置和站点源隔离；换域名、端口、浏览器或配置不会自动迁移。浏览器清理站点数据、无痕窗口关闭、配额回收或用户卸载浏览器都可能移除记录，因此必须保留用户可检查的 JSON 备份。软件不上传地图，不加入遥测或云账号。

## 验证边界

`tests/unit/M11_projectController.test.ts` 使用可延迟和可拒绝的存储端口，验证恢复门禁、A/B 保存、失败保留、独立版本 CAS、副本、视窗隔离和每标签页首选工程。这些测试无需 DOM。

真实 IndexedDB 事务、刷新恢复、真实鼠标/键盘操作、跨页面并发及对应故障注入，由独立浏览器验收验证。原生文件选择器授权、浏览器权限界面及真实同路径写回另见本地文件手工验收，不由上述控制器端口测试代替。
