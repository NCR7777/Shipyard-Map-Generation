# 分阶段实现计划

状态：待实现。首次只执行M0+M1，后续按验收推进。不可把M1闭环标为完整Level2工具。

## M0：契约和技术最小验证

检查已有仓库和AGENTS规则，确认包管理与开发环境。生成简短ADR：数据主权、坐标、几何来源、文件拆分、渲染器选择及版本策略。

落地schemas/map.schema.json初版、核心类型、字段说明和最小合法样例。Schema覆盖M2/M3实体的核心含义，但未实现的编辑能力明确标记。可选字段允许空集合，非法引用必须被语义验证发现。

先建立parse/validate/serialize、坐标转换和最小几何模块。证明可以无浏览器测试，不为了显示一个画布引入服务端或微服务。

交付：架构简图、真实文件结构、Schema、最小样例、可运行测试命令。完成后继续M1，不停在计划。

## M1：JSON往返与基础编辑竖向闭环

实现新建地图、米制画布、节点/道路折线、属性数值修改、选择移动、平移缩放、撤销重做、稳定JSON导入导出和错误定位。

实现无浏览器map:validate。提供一个synthetic样例和一个无效样例。执行“导出→外部修改节点坐标→CLI验证→重新导入”的端到端测试，证明图形与派生长度确实改变，而ID与连接不被破坏。

M1不要求底图配准、完整设施/资源编辑、三维或外部仿真。未实现的面板不显示为可用按钮。

通过A01—A08等与本阶段相关测试后提交已实现/未实现清单。

## M2：底图、设施和可靠人工编辑

增加底图导入、相似变换标定、来源记录、设施/障碍/作业区多边形、入口与服务点、道路连接/拆分、依赖删除、图层及测量。

增加自动恢复草稿、完整工程zip、丢失资产重绑定、外部修改冲突处理。增强控制点仿射配准可以在本阶段后半完成；独立核验精度缺失时报告未知。

提供两套人工设计参考样例，只有带实际底图与来源的用户地图可标reference_based；演示图始终synthetic。

## M3：Level2网络发布与外部仿真输入

实现路口转向、静态通行属性、资源区和容量定义、严格发布配置、结构化检查器、OD可达查询和网络级单车路径预览。

实现map:compile，输出不可变、确定性的有向网络和资源关联。冻结编译器版本、内容摘要和所用假设。完善servicePoint接入、未知参数策略与未授权穿越检查。

支持有明确边界的网络级预览，不实现复杂实时排程，不伪装完成长大构件扫掠验证。最终3套合成布局与错误样例需通过全部适用测试。

## M4：集成和维护能力

完善scenario/replay契约、业务CSV绑定适配器、变体管理、差异/迁移工具、性能基准和兼容性说明。

CSV导入必须先读取实际文件表头、单位和ID关系；缺少文件时只写适配器契约和测试夹具，不伪造原始数据。缺坐标的节点作为待布置对象，不导出为已核验真实布局。

对尚未实现的SUMO、GeoJSON、外部Python求解器协议或消息通道返回unsupported。用户选择一个具体集成后再实现，不一次建设全部适配器。

## M5：可选三维与VR后续工程

在不改写map.json核心语义的前提下，实现只读三维渲染适配器；用稳定ID、坐标基向量和1米标定物检查一致性。建筑高度和模型姿态有来源或显式展示假设。

之后才接运行状态、交互与VR。不得把“M0预留了height字段”报告成“M5已经支持三维数字孪生”。

## 每次交付格式

记录修改文件、实现能力、执行命令与结果、未运行检查、已知问题、剩余工作。与所要求阶段逐项对照；对真实环境限制如实说明。重要Schema变化附迁移与回归测试。
