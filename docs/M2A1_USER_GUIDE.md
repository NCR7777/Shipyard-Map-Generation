# M2A.1 服务目标与未应用输入使用指南

日期：2026-09-09。沿用 [M2A 空间编辑](M2A_USER_GUIDE.md) 和 M1.1 保存。本批新增功能以本指南为准；旧阶段报告仍是历史证据。本轮测试结果见 [阶段报告](M2A1_STAGE_REPORT.md)。

## 启动与地图版本

在工程根目录安装锁定依赖并启动：

```powershell
npm ci
npm run dev -- --host 127.0.0.1
```

打开终端显示的本地地址。新建地图使用 Schema 0.2.0；旧 0.1.0 JSON 和浏览器工程仍可原样导入、编辑和导出，不会因为打开编辑器自动升级。布局、节点与实体 ID 保持稳定；地图仍是 synthetic/草稿，不能据此声称现场运输可执行。

旧地图需要区域主归属或到达语义时，点击“升级到 0.2.0”，查看版本与 revision 差异，再点“保留原图并升级”。程序先成功建立浏览器原版备份，再提交一个可撤销升级事务；备份失败不应用升级。除版本和 revision 外不自动改写声明数据，不替用户补归属或假设。原文件关联解除，升级结果应“文件另存为”新文件；撤销不会重新授予旧文件写回关联。浏览器数据可能被清理，应同时保留原 JSON 文件。

命令行显式迁移使用两个不同路径，输出必须不存在：

```powershell
npm run map:migrate -- examples/M2A_synthetic.map.json M2A_upgraded.map.json
npm run map:validate -- M2A_upgraded.map.json
```

`map:migrate` 不修改输入，输出结构化差异和摘要；拒绝覆盖现有文件。具体版本与字段规则见 [兼容合同](M2A1_SCHEMA_COMPATIBILITY.md)。

## 本批示例与 CLI

`examples/M2A1_synthetic_service_targets.map.json` 明确标为 synthetic，包含设施内部道路目标与独立区域代理目标，可直接导入编辑器查看。它不是现场测绘或真实运输记录。`scripts/generate-M2A1-examples.ts` 通过领域命令生成该示例，便于复核来源。

```powershell
npm run map:validate -- examples/M2A1_synthetic_service_targets.map.json
npm run map:validate -- examples/M2A1_invalid_service_node.map.json
```

第一份是合法草稿，退出 0，同时保留未校验能力提示；第二份预期退出 1，并定位 `/servicePoints/sZoneUnload/nodeId`。不应修掉无效样例来让命令“成功”。

## 给建筑、堆场或区域添加运输目标

1. 选择已绘制的设施或业务区域。堆场/总组区可继续用设施类型 yard/assembly；独立 Zone 不会被自动改成设施。只选一个所属对象时创建表单预填其 ID，重叠和名称相同都不产生归属。
2. 点击“添加服务点”，确认主归属和“装载/卸载”等单一服务类型。本版 `kind` 是唯一服务能力，一个服务点尚不支持同时配置多种操作。
3. 选择定位方式。“已有节点”可从列表选择，或点击“在画布选择已有节点”后点实际节点/入口/服务点标记，复用其 nodeId。“新建节点”可输入 XYZ 米制坐标，或点击“在画布放置专用节点”点取坐标。
4. 在画布定位时只是暂存输入，尚未创建实体。中键平移、滚轮缩放；点击“返回创建表单”保留未完成输入。新节点落在旧道路中部不会自动拆路，同坐标不同 ID 也不会连通。
5. 设置到达语义后点击“创建服务点”。专用节点与服务点同一事务创建，一次撤销同时移除，重做复用相同 ID。任何硬校验失败都保留原地图。

入口与服务点是不同对象；设施面积不代表车辆入口，设施中心不会自动生成目标。添加入口同样支持画布选点与专用节点。

水域、障碍、禁入区或 passability=forbidden 的主归属仍保持原约束；添加服务点不会授权普通陆运进入。特殊船舶/水上等服务执行尚未支持，只能保留为有问题提示的草稿。

## 两种到达语义

**边界代理 node_proxy** 是新版本创建表单的推荐默认值。明确填写“代理到达说明”，选择未建模场内转运“纳入服务时长”或“明确忽略”。时长以后在独立 scenario 中设定；地图不保存本次作业剩余时间。代理通常位于建筑门外或堆场边界的道路节点，无需把点塞到厂房中心。位于厂房实体内部的代理会提示检查位置，不能用这项声明替代穿墙路线。

**显式内部路径 explicit_internal** 需要先绘制真实的内部道路。设施服务选择同设施入口，以该入口 nodeId 作为路径起点；区域/独立服务点直接声明 entryNodeId。按入口至服务 nodeId 的顺序添加内部路段和行驶方向。入口关联本身不产生路径或瞬移；路径长度由道路节点和折点派生。

缺入口、缺路径或未声明到达语义允许保存草稿并显示阻塞提示；悬空引用、序列端点不连续、禁止方向等硬错误拒绝应用或导入。本阶段没有全网路径发布。也可以明确选择“未声明（草稿）”逐步补图，不能把该草稿当作已配置可运行任务。

## 接路提示与编辑已有目标

从对象列表选择服务点，右侧“已提交目标的接路检查”展示其主归属、节点、显式端点道路数、到达抽象和内部路径长度。提示对应已提交地图，未应用表单值不能改变该结果。

- `blocked`：至少存在已知缺项/错误，例如无显式道路端点、没有入向弧、未知方向、内部接续未声明或受限区域。
- `unchecked`：当前检查没有发现上述阻塞，但完整起点可达性、允许转向、资源执行、车货净空与公共接入仍未验证。
- 内部路径 `continuous` 只描述声明节点序列连续；不是“全网可达”或“实际安全”。

要接入旧道路中部，选择那条道路，用既有“拆分道路”功能输入准确弧长并复用目标节点，或从目标节点显式绘制新道路。禁止把贴近折线当作已经连接。内部路径已引用的道路目前拒绝拆分，应先明确修改路径声明再调整道路，不自动改写未知关联。

服务点数值移动仍编辑其权威节点 XYZ，所有共享该 nodeId 的道路端点和关联点同步。右侧可修改名称、主归属、类型、nodeId、入口和到达声明，点击“应用属性”后才进入事务、保存及导出。

## 区域成员与复制删除

区域成员从服务点的 zoneId 派生，没有第二套可编辑成员名单。设施/区域各有独立移动策略：“仅边界”明确保留成员节点；“边界和关联节点”移动成员目标节点。影响预览显示受影响道路及共享节点。此策略不自动选入所有内部道路折点或外部接路节点；需要整组移动时显式多选道路与节点并检查派生几何。

复制设施/区域自动纳入成员点、权威节点并分配新 ID；外部道路不隐式复制。单独复制服务点需明确允许保留原主归属。服务点声明内部路径时，须显式把全部内部路段选入复制范围，否则拒绝事务，避免复制后回连旧路径。

删除设施/区域有成员时必须明确选择“一并删除设施或区域成员入口和服务点”；仍被其他对象使用的节点不能被偷偷清除。失败保留整张地图和历史。复杂资源/未知行为地图继续只读，升级不会移除能力门禁。

## 未应用输入与保存

属性、地图名称、未完成道路/多边形以及操作表单不属于已提交地图。切换对象、工具、撤销重做或相关编辑操作时，出现“未应用输入保护”：默认取消，保留原对象、工具和输入；点击“丢弃未应用输入并继续”才执行切换。属性/地图名称尚未应用时禁拖动，防止一次拖动重建面板而丢失输入。未完成道路/多边形或服务创建时，先完成或取消当前操作，再编辑底层属性与地图名称。

“保存工程”遇到暂存输入会明确询问；“仅保存已提交地图”保存已有事务，表单继续保留。导出同样只包含已提交地图；不要把下载提示解读为暂存属性已保存。重新加载浏览器工程仍只恢复已提交地图。对输入的保护不等于把暂存字段持久化。

已有自动草稿、多项目、CAS 冲突保护和外部文件检查保留。系统原生文件授权/任意磁盘写回仍按 [手工验收](M11_NATIVE_FILE_ACCEPTANCE.md) 单独核验，自动化选择器替身不能替代该验收。

## 当前边界

本批没有车辆调度、装卸计时、资源占用执行、完整路网发布或运行回放。到达服务节点以后何时等待、开始、完成装卸，是 [M3A 后续计划](M3A_IMPLEMENTATION_PLAN.md) 的事件引擎工作。静态 map、scenario、runtime 与 editor-state 保持分离；底图和 ZIP 留待 M2B，未实现 3D、VR 或复杂优化器。
