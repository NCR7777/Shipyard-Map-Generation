## 顺序调整

计划原为 P3 → P4。P2 完成后已能描图，但只能「导出副本」保留修改，刷新即丢失；在能保存之前，P3 的业务对象再多也无法用于实际工作。旧版在这一层还有原有失败（刷新后恢复关联），宜尽早查清。因此先做 P4（拆为 P4a 浏览器工程、P4b 本地文件），再做 P3。依据是用户 2026-09-24 的授权：「我授权你可以进行全仓重写，你可以选择最优的方式实现我的所有功能，包括美观、人机交互逻辑、性能等，以及保留后续升级以及接入调度和仿真接口」；调整已在对话中告知用户，并说明若希望先做 P3 可以调回。独立审查认为调整站得住：P4a 保存整张地图与视图，与 P3 的业务对象、拓扑相互独立，P3 不会让 P4a 返工。

## 范围与改动

- **复用内核**：存储与恢复逻辑全部来自内核的 `ProjectController` 与 `IndexedDBProjectStore`（与旧版相同，P0 原样移植），库名 `shipyard-map-studio`（P1B 起就与旧版的 `shipyard-map-projects` 隔离）。界面层（`src/app/state/project.ts`）只决定何时保存、如何显示和恢复。旧版行为调研整理在会话临时目录（scratchpad `p4/old_project_spec.md`）。
- **工程**：打开地图（JSON 或 zip 包）即建立浏览器工程；「文件 › 新建地图…」建立格式 0.3.0 的空白地图（原点居中，约 4 px/m）；「文件 › 浏览器工程…」（Ctrl+Shift+O）列出本浏览器中的工程（最近更新在前），点击切换；点当前工程不做任何事（保留撤销历史）。切换或打开新地图前，先把当前工程未写入的修改写入；写入失败（冲突或存储错误）时拒绝切换并说明。
- **自动保存**：地图内容与上次写入的草稿不同时，600 ms 后写入草稿；保存串行，保存期间的新修改在保存完成后再写。视图（相机、显示设置、单位、底图显示与不透明度、对照模式）另有 600 ms 防抖，只写视图记录，不产生撤销步骤。
- **保存（Ctrl+S）**：写入检查点，保留上一个检查点（内核的 draft / checkpoint / previousCheckpoint）。在输入框里按 Ctrl+S 也有效：先让输入框失焦（按 P2d 的规则提交），再保存。
- **刷新后恢复**：按「本标签页上次的工程（sessionStorage）→ 最近工程」恢复地图、相机（原样）、显示设置、单位、底图显示；撤销历史、选择、工具不恢复（与旧版相同）。恢复后到用户修改之前不写入任何东西（地图哈希等于草稿，视图与恢复值相同）。
- **恢复失败**：弹「恢复浏览器工程」，说明原因；浏览器中的记录不改动。可「重试恢复」，或「仅在本页继续」——此后打开的地图只在内存中，保存时提示用「导出副本」。
- **多标签页**：窗口获得焦点时检查另一标签页是否保存过此工程（内核的 `checkExternalVersion`，自己的保存进行中时不算冲突）；写入时按存储版本比较并设置，另一方先写则本次被拒。冲突后停止自动保存，画布上方出现横幅：「另存为恢复副本」（本页地图另存为「…（恢复副本）」，不切换）、「载入浏览器中的版本…」（确认后放弃本页修改）。
- **状态栏**：正在恢复 / 有修改待保存 / 保存中… / 已自动保存（草稿）/ 已保存（与检查点相同）/ 保存失败：… / 冲突 / 只在本页内存中；视图保存失败只作提醒，不影响地图。
- **离开页面**：只在有未写入的修改（尚在 600 ms 内、保存失败、冲突、仅内存）或正在保存时提示；已自动保存后直接离开。
- **底图**：图片随工程存储（按工程 ID 与内容哈希）；P1B 时按地图 ID 存下的图片仍可找到（内核按哈希跨工程复制）。刷新后自动载入，不必重新选择。
- **单位**：P2d 时承载、限速的显示单位存在浏览器本地；现在随工程的视图保存（内核 `EditorState.propertyUnits`，与旧版相同）。
- **显示设置按工程**：每张地图有自己的显示设置（图层隐藏与锁定、网格、路宽默认值等）；新打开的地图用默认设置（与旧版相同）。P2a 的「锁定图层与只读地图」用例原来假定锁定会带到第二张地图，已按新行为改为断言新地图未锁定（用例目的「只读地图拒绝编辑」不变）。
- **相机**：画布在相机停下后把它写入状态（供视图保存）；新增「恢复相机」的请求。空白地图没有可适配的范围时，把原点放在画面中央。
- **升级前备份**：选道路、弯道、建筑、区域工具时弹出的「升级地图格式」，确认后先把升级前的原图另存为「…（恢复副本）」，成功后才升级；另存失败则不升级。刚打开、还没有检查点的地图，升级后自动保存会覆盖草稿，原图原来只剩内存里的撤销（审查指出）；旧版同样先备份。解除本地文件关联的一步在 P4b。
- **仅内存模式**：打开另一张地图或切换工程时，若有未导出的修改，先问「取消 / 先导出副本再打开 / 放弃修改并打开」（旧版的「未保存编辑冲突」）；新打开的地图用默认显示设置。
- **恢复失败时的其他工程**：恢复失败对话框列出浏览器中的全部工程（直接读存储，不经过已失败的恢复），可以选一个打开；它随后成为新标签页默认打开的工程。仅内存模式下的「浏览器工程…」也这样列出。
- **说明**：帮助面板的显示约定加入浏览器工程与多标签页的说明；空白画布提供「浏览器工程…」「新建地图…」「打开地图…」。

## 与旧版的差异（有意）

- 工作台布局（`EditorState.workbench`：栏宽、折叠）不保存；新版的栏宽在页面内调整，不随工程保存。
- 切换工程前，旧版保存检查点，新版保存草稿（检查点仍由 Ctrl+S 决定）。
- 离开提示不覆盖 600 ms 内尚未写入的视图（相机、显示设置）；只覆盖地图。
- 仅内存模式下载入底图仍可能把图片缓存进 IndexedDB（按地图 ID），地图本身不写入。

## 设计决定

- 旧版的「未应用输入保护」对话框不再需要：P2d 起字段离开即提交；未完成的绘制草稿本来就不属于地图，保存只保存已提交的地图。
- 自动保存在冲突与存储错误后停止，直到用户显式保存或重新载入（与旧版相同）；视图保存失败与「地图已存、附属记录未存」不阻止地图的自动保存（旧版会一并停止）。
- 不提供删除工程：内核的存储端口没有删除操作，内核目录保持与 2d21c16 一致；列为已知限制。
- 「另存为副本」没有做：内核的副本接口固定命名为「（恢复副本）」，用作主动分叉会误导；需要时在 P4b 或以后按名称另做。

## 已知限制

- 不能删除浏览器工程（内核存储端口没有删除操作）；工程会随打开的地图增多。
- 没有「另存为副本」（见设计决定）。
- 切换工程前的写入若失败（冲突、存储错误），会拒绝切换；需要先处理保存状态或导出副本。
- 窗口尺寸与保存时不同时，恢复的相机按原偏移显示，地图可能不在中央。
- 本地文件的关联、写回、外部修改检测在 P4b。
