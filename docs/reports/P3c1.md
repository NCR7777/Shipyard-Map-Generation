# P3c1 阶段报告：拓扑编辑（通过）

日期：2026-09-27。执行者：主会话。前置：P3b2c 已通过，本地提交 143e9a1，已推送 Shipyard-Map-Generation main 5e73a68（本地 `publish/map-studio-20260927`）。审查：RV31「修正后通过」（4 项重要、12 项次要、3 项建议）→ 修正 → 增量复审「通过」（3 项次要、4 项建议，提交前已处理，见下）。

## 来由

用户 2026-09-27「继续」。计划的 P3c 路网拓扑包括：拆分、合并、连接、保持连通删除节点、单向与反转、路口转向三态矩阵、画布点选路口、绘图时显示隐藏的普通节点、节点吸附的高度，以及 P3i 审查留下的「拖动入口接入段的弯曲柄会钉住建筑」。

调研结论：内核已有拆分（`splitRoad`）、合并（`mergeNodes`）、接入（`connectNodeToRoad`）、保持连通删除（`suppressDegree2Node`）的命令与转向枚举，只缺界面；转向没有任何增删改命令，矩阵要先扩展内核。据此把 P3c 拆成 P3c1（本阶段，不改内核）与 P3c2（路口与转向）。旧工具的做法：拆分在对话框里输入里程或在画布拾取；合并、接入要打开「拓扑吸附」开关后拖动节点，或用按钮，再在确认对话框里选保留对象、勾选是否允许新增转向。

## 改动

- 新模块 `src/app/canvas/topology.ts`：
  - `dropTarget`：拖动的节点松开处的目标：另一个节点（同一高度）或道路中部，在吸附距离内、显示且未锁定的图层上；与它共用道路的节点（合并会成自环）和它自己的道路不作目标；
  - `dropCommand`：合并（拖动的节点并入目标节点，目标留在原处）或接入（节点移到道路上、道路在那里拆开；节点已有单节点路口时沿用它的编号，内核要求）；
  - `suppressCommand`：恰好连着两条道路的节点，默认保留第一条；
  - `proposedTurns`、`withTurns`：内核建议的新增转向（`enumerateMergeTurns`、`enumerateConnectionTurns`：不含掉头、遵守单向），按勾选批准或不批准；
  - `selectionTopology`：编辑菜单用：两个节点（先选的保留）、一个节点加一条道路（接到道路上离节点最近的点）、一个节点；不可用时说明原因；
  - `splitSpot`、`splitCommand`：拆分工具的目标与命令；拖放与拆分的位置取到毫米（与拖动移动相同，坐标整洁，没有像素换算的零头）；
  - `nodeConflict`：两个节点类型或扩展数据不同时内核不合并（任一方向），给出原因与可行做法；拖放目标与编辑菜单都用它预先判断；
  - `topologyRefusal`：内核拒绝的白话说明：两条道路不能合成一条时，指出方向、宽度等物理值（写出两边的值；数值相同只是依据不同时写「…的依据不同」）、资源、扩展中哪几项不同（按内核的比较方式，方向按合成后的路读），并分情况给出指引：只有属性栏能改的差别时让用户改一致，有资源或扩展数据的差别时说明属性栏改不了、保留节点不影响通行（第一版一律让用户去属性栏改，EA01 hanwha 54 次拒绝全是扩展数据不同，TIF 上 7 次宽度数值其实相同，RV31 重要 I3）；节点类型不同；缺直行许可；方向待配置；节点上有入口或作业点；内部道路；重复道路；自环。
- 拆分工具（`drawingTools.ts`、`registry.ts`，工具栏「拆分」，快捷键 X）：点道路中部在那里拆成两段，新节点接着两段，属性与直行保留；点在节点上不拆并说明（节点图层隐藏时也按节点算，第一版在路口旁会拆出 0.1 m 的极短段，RV31 M5）；道路图层隐藏、道路或节点图层锁定时预览与点选都说明（第一版预览不看锁定，RV31 M6）；预览显示拆分点与「距起点 x m / 全长 y m」；每点一次一个撤销步骤，Esc 或 Enter 结束。拆分与接入的位置按沿路里程取到毫米（斜路上的节点坐标仍会有长小数，RV31 M11 指出第一版报告的「坐标整洁」说法不准）。
- 拖放连接（`CanvasView.tsx`）：拖动单个节点（道路端点可直接拖，P3f2 起）时，靠近目标显示绿圈与「松开：并入节点「…」」或「松开：接到道路「…」」，节点预览吸到目标上；松开后节点不动，弹出确认对话框。拖动中按住 Alt，或只在松开时按住 Alt，都只移动（按指针位置）；Shift 限轴时不吸附；关闭「吸附节点」时不吸附；按下时就按住 Alt 仍是原有的复制（第一版提示写「Alt 只移动」，照做会复制出一个看不见的节点，RV31 重要 I2）。类型或扩展数据不同的节点（内核不合并）不显示绿圈，只显示「不能并入「…」」，松开后节点放回原处并说明原因与可行做法（用道路工具从它画这一段）（第一版照样显示绿圈，在真实地图上多数合并被内核拒绝，RV31 重要 I1）。相当于旧工具「拓扑吸附」开关打开时的行为，不需要开关。
- 编辑菜单（`registry.ts`）：「合并节点…」「把节点接到道路…」「删除节点并接通两条道路…」，选择不符时灰显并说明原因。节点的属性栏有「删除节点并接通两条道路」按钮，并提示可以拖放合并或接入。
- 确认对话框（`EditDialogs.tsx` 的 `TopologyDialog`，三种编辑共用）：
  - 用文字说明会发生什么（例如「「孤一」并入「…」：连到「孤一」的 1 条道路改连「…」…」、接入时节点移动多少米、道路在距起点多少米处拆开、合成后保留哪条道路的编号与属性）；
  - 合并可换保留的节点，删除节点可换保留的道路；
  - 合并与接入时列出新增的转向，默认全部允许，与画路接上节点时相同（`quickTraceRoad` 也自动加非掉头转向）；可整体取消，也可展开逐个取消（RV31 建议 S1；内核接受建议列表的任意子集）；有未允许的转向时说明它们保持「未声明」、按已确认转向找路时不会经过这里；接入时转向里被拆开的道路写作「…（前段）」「…（后段）」（第一版显示原始编号，RV31 M3）；
  - 内核的影响列表（与删除对话框共用 `Impact` 部件，从删除对话框抽出；这次编辑新建的对象显示为「（新建）」）；写到锁定图层时直接说明并禁用确认（RV31 M9）；被拒时显示白话原因（`topologyRefusal`，其次入口的说明 `refusalMessage`，再其次内核原文）；合并说明只在被并掉的节点上有入口或作业点时才提它们（RV31 M8）；
  - 打开后地图有改动（撤销、别的编辑）则作废（复用删除对话框同文件的 `stale()` 与 `useOpenedToken()`，store 里只存命令；RV31 建议 S3）；确认后选中保留的节点或道路，提示允许的转向数；一个撤销步骤，撤销标签为编辑名称。
- 属性栏（`Inspector.tsx`）：单向道路的方向旁「反转方向」（改为另一方向，几何不变；另一方向被转向规则禁止时不可用并说明）。
- 显示：画路、弯道、拆分工具以及拖动单个节点时，被隐藏的普通节点显示出来（仍按缩放省略过密的），便于看清可以接到哪里（`CanvasView.tsx` 向渲染传 `showOrdinaryNodes`）。
- 吸附的高度（`drafting.ts` 的 `snapTarget`、`drawingTools.ts` 的 `resolvePoint`）：第一点可吸附任何高度的节点与道路，之后吸附与自由点都沿用第一点的高度（原先只吸附高度为 0 的；与旧工具相同）。
- 入口接入段的形状检查（`CanvasView.tsx` 的 `commitEdit`、`handles.ts` 的 `bendStopsMoving`）：从插入折点推广到所有改路形的编辑（拖动弯曲柄、切向柄、折点等），会使建筑不能移动时拒绝并说明，说明按具体编辑写（「弯曲道路后「…」将不能移动」），并给出变通办法：先用拆分工具把它拆成两段，接入口的那段保持直线，再改另一段（审查者核实可行，RV31 M2）。只在直路改成非直路时检查：已经弯的路原本就不能随建筑伸缩，直路保持直线也不会钉住（第一版每次改路形都跑两次内核检查，TIF 上提交时间约翻倍，RV31 M1）。

- 属性栏节点的拖放提示只对没有入口、作业点的节点显示（RV31 M7）。

## 与计划和旧工具的差别（执行者裁定）

- 「此处开始变宽」（旧工具的一个拆分变体：拆开并把一侧改宽）没有做：拆分后在属性栏改那一段的宽度，两步完成，不值得一个单独的命令。
- 旧工具的「拓扑吸附」是一个开关；本工具拖放单个节点时总是提示，按 Alt 只移动，与画路时 Alt 暂停吸附一致。
- 旧工具的拆分可以输入里程、复用已有节点；本工具在画布上点选（里程取到毫米），不复用节点（把已有节点接到道路上可用拖放接入完成）。
- 「此处开始变宽」的理由更正（RV31 S2）：内核已有 `splitRoadAndSetWidth`，不做是因为界面上「拆分、再改一段的宽度」两步即可，不是因为内核缺命令。
- 新增转向默认允许（旧工具默认不允许、要勾选）。理由：本工具画路接上节点时内核已经自动允许非掉头转向（`drawingDefaults.ts` 166–182 行），拖放连接与画路是同一件事，默认不同会让同样的连接在调度里一个可走一个不可走；对话框列出这些转向，可以整体或逐个取消。RV31 评估同意：真实地图的路口全是显式转向，已确认路线要求显式允许（`pathPreview.ts` 183–189 行），默认不允许会让新接的路悄悄走不通；真实断头合并中没有偏转大于 135° 的建议转向。
- 待用户决定（RV31 重要 I1 的根源）：内核只合并同类型、同扩展数据的节点，旧内核测试 TE01「rejects merge … conflicting nodes」明确要求普通节点不能并入路口节点。按工程规则不改这条测试来放宽内核，本阶段在界面上预先说明原因。代价：真实地图上多数节点是路口、入口或作业节点，新画道路的普通端点不能拖放并入它们，要用道路工具从那个节点画（画路接到已有节点时内核直接用那个节点）。放宽方案：没有扩展数据的普通节点并入任何节点时沿用目标的类型（不丢信息），需改内核与 TE01 这一断言，请用户决定。

## 已知限制

- 转向只能在合并与接入时一并批准；已有路口的转向还不能单独改（P3c2）。「删除节点并接通」要求节点上已有两条道路之间的直行许可，缺的时候要等 P3c2 才能声明。
- 拖放目标取吸附距离内最近的节点，其次道路；与拖动的节点共用道路的节点不提示（合并会成自环），想把它们合成一个点要先删那条路。
- 接入会把节点移到道路上；节点是入口或作业点所在节点时，按内核规则可能被拒（例如入口会离开建筑轮廓）。
- 显示被隐藏的普通节点时仍按缩放省略过密的；放大后才看得到全部。
- 面积工具（建筑、区域）的第一点也吸附任何高度的节点，面积随之画在那个高度（与旧工具相同；真实地图的高度都是 0）。
- 拖放吸附随「吸附节点」选项，这个选项只在绘图工具的选项里出现；选择工具下要先切到画路等工具改它。
- 真实地图上多数节点是路口、入口或作业节点，新画道路的普通端点不能拖放并入它们（内核规则，见「待用户决定」），要用道路工具从那个节点画。
