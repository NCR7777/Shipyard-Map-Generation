## 范围与改动

- **与 `../map` 的存储隔离**（`vite.config.ts`、`src/app/state/backgrounds.ts`）：
  - 开发与预览固定使用 5180 端口。旧工具用 5173 端口，两者都设了 `strictPort`；在此之前，旧工具不运行时新工具会占用 5173，与旧工具同源，共用浏览器存储；
  - 浏览器数据库名改为 `shipyard-map-studio`，由调用方传入，内核适配器 `IndexedDBProjectStore` 本身不改；
  - P1 的界面没有读写过任何浏览器存储，所以此前没有造成影响；
  - 已写入 AGENTS.md 与 README.md。
- **打开**（`src/app/files/open.ts`、`src/app/files/zip.ts`）：
  - 文件对话框和拖放都可以一次选多个文件：地图 JSON、zip 包、PNG / JPEG / WebP 图片；
  - 同时有 `schemaVersion`、`mapId`、`metadata` 的 JSON 才算地图，同目录的 `calibration.json`、`receipt.json`、`compiled-map.json` 会被跳过；
  - 候选地图有多张时弹出选择框，只有一张时直接打开；
  - zip：支持未压缩与 deflate（浏览器原生 `DecompressionStream`）；单个条目按声明大小流式解压，超出即停止；条目的数据区不得互相重叠（否则多条目录记录可以指向同一段数据，总量不受限）；结束记录必须与它描述的目录首尾相接，注释里的仿冒签名不算；解压失败给出条目名；不带 UTF-8 标志的文件名先按 UTF-8、失败再按 GBK 解码；不支持 ZIP64 与加密；包内非 UTF-8 的其他 JSON 直接跳过；
  - zip 包内所有图片都按内容与所选地图比对，不限所在目录（验收记录里的地图与图片不在同一目录）；图片逐张读取，比对不上的立即丢弃，不逐张报错；所有底图都已就绪时不再读取，找齐后提前停止；包内图片合计超过 512 MiB 时不自动读取，提示另外选择；
  - 选择框的每一项附摘要「底图 N 层 · 对象 M 个」，导入前的空地图一眼可辨。
- **图片匹配与缓存**（`src/app/state/backgrounds.ts`）：
  - 先对原始字节算 SHA-256，与地图中声明的图片资源匹配，不看文件名；匹配上的再用内核的 `rasterBytes` 校验（格式、尺寸上限、EXIF 方向）并核对像素尺寸与格式，失败一定报告（包括 zip 的静默模式）；
  - 一次打开只有一个提示位置：图片步骤报告过就以它为准；否则把「包内图片未读取」和「底图缺图」合并成一条；
  - 匹配成功后存入本工具的浏览器数据库，下次打开同一地图自动载入；存储不可用时仍然显示，并提示下次需要重新选择；读取时数据库不可用显示为「缺图」并说明原因，只有已存字节校验失败才显示「错误」；
  - 打开地图后仍有底图缺图、又没有载入任何图片时，提示条说明去「图层」页选择原图；
  - 解码为 `ImageBitmap`：它一直保持解码状态，而不在页面中的 `<img>` 可能被浏览器丢弃解码结果，平移时再重新解码；
  - 换地图时释放新地图用不到的图片；迟到的载入结果如果已不属于当前地图，直接释放；生成金字塔中途失败时释放已生成的层；载入过程中换了地图，不再提示「已载入」。
- **绘制**（`src/app/canvas/renderer.ts`）：
  - 底图画在矢量下方，在世界坐标变换上再叠加 `imageToWorld`；
  - 图像金字塔：载入后在后台生成 1/2、1/4……直到约 1024 px 的缩小副本；绘制时在「最多缩小一半」（每个屏幕像素对应 1 到 2 个层级像素）的前提下选最小的层，并拉伸到原图范围；放大到原图像素比屏幕像素还大时一律用原图。原因见下方性能一节；
  - 显示底图时网格不透明度降到 0.3；
  - 影像对照模式：道路填充 ×0.25，建筑与区域 ×24/53，与旧版一致。
- **界面**：
  - 图层页新增「底图」区：每层显示状态（就绪、缺图、载入中、不支持、错误）、显示开关、不透明度、适应底图；缺图时说明需要的原图（尺寸与 SHA-256 前缀，文件名不限），并给出「选择图片」按钮；不支持时列出内核给的原因；
  - 同一图片、同一位置的重复图层给出提示（韩华 TIF 地图就有两层完全相同），但仍然按地图如实画两次；同名图层附「第 N 层」；
  - 命令：选择底图图片、适应底图、显示/隐藏底图；
  - 没有任何矢量内容的地图，「适应」改为适应底图；
  - 滑块统一改称「不透明度」：数值越大越不透明，原来的「透明度」说法与数值方向相反。
- **切换地图时**：每层的显示与不透明度设置重置，影像对照是全局设置，保留。

## 性能验收

方法同 P1（`tests/perf/compare.perf.ts`，两边都是生产构建，4 轮交替背靠背，1600×1000 视口）。本阶段新增 `PERF_BACKGROUND`：两边各自通过自己的界面载入同一张底图，旧版用「重新关联同一图片」。地图为 TIF 韩华 `map.json`（95 栋建筑、688 条道路、两层相同的 4105×4351 底图）。单位 ms，帧间隔受 240 Hz 量化（4.2 ms 一档）。

**测量时本机满载**：用户的 D4 E4 实验（多进程）正在运行，CPU 占用 99%–100%，没有中断它。两边交替测量，负载对两边的影响相近；机器空闲后应复测一次再作最终结论。

带底图（图像金字塔之后）：

| | 平移 p50 | 平移 p95 | 平移最大 | 缩放 p95 | 缩放最大 | 缩放长任务合计 |
| --- | --- | --- | --- | --- | --- | --- |
| ../map（4 轮） | 4.2 / 4.2 / 4.3 / 4.3 | 12.6 / 12.5 / 12.8 / 12.5 | 54.3 / 54.1 / 54.2 / 58.3 | 25.1 / 25.0 / 37.5 / 29.2 | 174.9 / 162.5 / 154.2 / 175.0 | 284 / 275 / 259 / 286 |
| map-studio（4 轮） | 4.2 / 4.2 / 4.2 / 4.2 | 4.3 / 4.3 / 4.3 / 4.2 | 4.3 / 8.3 / 8.3 / 8.2 | 8.3 / 8.3 / 12.4 / 12.5 | 41.7 / 45.8 / 41.7 / 45.8 | 0 / 0 / 0 / 0 |

不带底图（确认纯矢量没有退步）：studio 平移 p95 4.2–4.4、缩放 p95 4.3–4.6；map 平移 p95 12.4–13.1、缩放 p95 20.8–20.9。

排查过程：

1. 第一版直接画原图：studio 缩放时每轮有一次 83–96 ms 的长任务，不带底图时为 0。
2. 逐次记录 `drawImage` 的耗时，都在 4 ms 以内；CPU 剖析显示 122 ms 算在 `setTransform` 上，这是浏览器在清空画布命令时，按新比例重新采样整张 4105×4351 原图。
3. 加入图像金字塔后，长任务在 3 次复测中都是 0，缩放最大帧从 83–96 降到 42–46。
4. 剩余的 42–46 ms 来自缩放过程中第一次用到原图层的一两帧（记录到的慢帧正好出现在比例跨过 0.5 的时候）。在另一张小画布上预先绘制各层没有效果，已撤回。
5. 放大后平移（描图时的实际状态，一直使用原图层）完全流畅：0.7 px/m 与 3 px/m 下帧间隔 p95 为 4.3–4.8、最大 4.4–7.6，所以这是一次性开销，不影响描图。
6. 无头与有界面的 Chrome 用的都是本机显卡（ANGLE / D3D11），测量结果不是软件渲染的假象。

## 已知限制

- 缩放时第一次用到原图层会有一两帧约 40 ms 的一次性开销（见上）；
- 地图中的重复图层按地图如实绘制两次，只给提示；删除图层在 P3；
- 底图偏好（显隐、不透明度、影像对照）不保存，切换地图时重置每层设置（P4）；
- 旧工具浏览器存储里的图片无法直接读取（不同源），需要原图片或旧工具导出的 zip 包；
- 性能数据是在满载下测的，机器空闲后需要复测。
