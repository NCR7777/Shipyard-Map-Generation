# P2d 阶段报告：属性编辑（已通过）

日期：2026-09-24。执行者：主会话。前置：P2c 已通过，本地提交 0f2c1a3。审查：独立审查「修正后通过，需要复审」（7 项重要、4 项次要）；复审确认 7 项都已修好并在真实高级地图上核实，但修正新引入 1 项重要（「全部改为未知」删掉说明），另提 6 项次要；修正见「审查修正」与「复审修正」，第 1 项需要针对性复审。

## 范围与改动

- **提交方式**（`src/app/ui/PropertyFields.tsx`）：属性栏的每个字段单独提交，按 Enter 或离开输入框即提交，一步撤销；Esc 恢复原值。旧版要逐个点「应用属性」，未应用时切换选择会弹「未应用输入保护」对话框，新版不再需要。
  - 输入法组字时的 Enter、Esc 不提交也不取消（`isComposing` 或 keyCode 229），文本字段与物理参数字段都如此；
  - 输入本身有问题（例如宽度为 0、坐标不是数）时：按 Enter 保留输入并在字段下方说明，方便改正；离开输入框则提示「已恢复原值」并恢复；
  - 内核拒绝时，提示给出拒绝的第一条错误（`refusalMessage`）。此前统一入口显示的是问题列表的第一条，而列表开头常是关于地图其余部分的警告（例如「heightLimitM 未知；仅作草稿」），真正的原因被盖住；这一修正对 P2a 以来的所有编辑都生效。字段随后恢复为地图中的值；
  - 只有输入过、且尚未提交的字段才会被读取；提交之后、或按 Esc 之后，地图变化（撤销、其他编辑）会立即反映到字段上；
  - 字段按「地图 + 对象」区分实例：输入了但没有提交的文字，在打开另一张地图时丢弃，不会写进新地图。焦点在输入框时点画布或目录选另一个对象，输入框先失焦并提交到原对象（一步撤销），再改变选择；按对象区分实例是防御性的，审查者没有找到不失焦就换选择的路径；
  - 提交后字段立即显示地图中的值，即使显示的字符串没有变（X 为 104.568 时输入 104.5680001，存全精度、仍显示 104.568）。
- **各类对象的字段**（`src/app/ui/Inspector.tsx`）：
  - 地图：名称（`renameMap`，不能为空）；
  - 节点：名称，X、Y 坐标（`updateNode`）；Z 只显示：非平面的局部修改会被内核拒绝（`LOCAL_NONPLANAR_EDIT`，审查者在三张真实地图上各 8/8 被拒），旧版也不开放 Z；
  - 道路：名称，方向（待配置 / 沿箭头单向 / 反向单向 / 双向），宽度、限高、承载、限速四个物理参数；
    - 路口转向规则按相反方向使用这条路时，对应的单向选项仍列出但不可选，并说明原因（`blockedDirections`：一条路只能改为所有转向规则都使用的那个方向）。审查者实测：三张真实地图上各 80 次方向修改全部被 `ARC_DIRECTION_CONFLICT` 拒绝；
  - 建筑：名称，兼容类型（厂房、其他；0.3.0 地图另有「建筑」；旧类型只对已有它的建筑显示），高度；
  - 区域：名称，兼容类型（0.3.0 地图另有「未分类」），通行声明；
  - 入口：名称；作业点：名称、作业类型。规划数据固定了作业类型时（声明了装载和卸载能力的须为「其他」，停车泊位引用的须为「停车」，`fixedServiceKind`），只显示类型并说明原因。审查者实测：hanwha_v01 上 110/110、中集上 15 次修改作业类型都被 `STATIC_CONTENTS_INVALID` 拒绝，提示是技术路径；
  - 字段顺序改为先写对象是什么（名称、分类、类型、参数），再写轮廓（外包尺寸、净面积、轮廓编辑）。
- **物理参数**（`src/app/state/properties.ts`）：
  - 状态四选一：已声明、未知、明确无限制、不适用。选「已声明」只是打开数值框，输入数值后才提交；选其他状态立即提交；选回地图中原来的状态不提交；
  - 未知、明确无限制、不适用的说明文字可以编辑（例如「影像中路缘不可辨」），编辑后去掉首尾空白，清空即删除说明；没有编辑过的说明原样保留；
  - 清空已声明的数值表示改为未知；
  - 单位：长度 m；承载 t 或 kg，限速 km/h 或 m/s，切换只影响显示，偏好保存在本浏览器。输入的数只换算一次后存为 kg、m/s，不取整；显示超出当前单位的有限范围时说明原因，不改存储值；
  - 新数值没有指定来源时，附带一条设计假设（「道路参数设计假设」「建筑参数设计假设」），由内核创建来源；
  - 已声明的数值下方有「依据」选择框，显示当前来源，改选即记录新的依据，数值不变，撤销按钮写作「修改宽度依据」；同名来源附上编号和被引用的字段数（`sourceLabels`），以免选到外观相同的另一项；
  - 把显示出来的数原样输回、或输入与存储值相同的数，不产生修改，也不新建来源。
- **道路批量**：
  - 多选的全是道路时，属性栏出现「批量修改 N 条道路」：宽度（各不相同时输入框为空，占位文字为「各不相同」）与方向（各不相同时显示「各不相同」），一次提交、一步撤销；内核跳过已是该值的道路，一条被拒则全部不改；
  - 有已声明宽度的道路时，提供「把已声明的宽度改为未知（N 条）」：只改已声明的，本来就是未知、明确无限制、不适用的道路连同说明都不动；
  - 批量方向同样按转向规则禁用：任一所选道路不允许的单向，在批量里不可选；
  - 单条道路有「选中连续的 N 段」：用内核的 `continuousRoadIds`，方向、宽度等参数相同、首尾相接、中间节点没有业务点的路段一起选中。
- **权限**：只读地图、锁定图层时，属性栏显示与之前相同的只读值，没有输入框；显示也按所选单位。
- **说明**：帮助面板加入属性栏的两条操作说明。
- **P2c 测试的调整**：P2c 的道路控制柄 e2e 用 `toContainText('12 m')` 读宽度；P2d 把宽度改成了输入框，值不在文本内容里，全量门禁中这条失败。改为读输入框的值（12 → 18 → 撤销后 12），并新增断言：拖动宽度柄后「宽度依据」选中的是「人工影像宽度估计」（此前只有单测覆盖）。审查者确认强度不低于原来。

## 门禁中发现的缺陷（渲染器，P1 以来就有）

- **现象**：全量门禁中 P2a「rotate turns the selection…」失败，复审者的 P2c 第一条也出现同样现象：打开地图后第一次点击 (35, 70) 没有选中，属性栏仍是「地图概览」。两条都不是 P2d 改的测试，重跑通过，但不是单纯的负载超时（另一次重跑失败是 `page.goto` 超时，是另一种已知现象）。
- **根因**：画布的「当前显示的对象」（`visibleKeys`，点击只命中显示出来的对象）只在绘制一帧时计算，而绘制在 `requestAnimationFrame` 里。地图打开后、第一帧画出之前，这个集合是空的（换地图时则是上一张地图的）；相机数据已经写到元素上，测试据此点击，却什么也命中不了。满载时帧被推迟，这个空档变长，所以偶发。用户在极忙的机器上打开地图后立即点击，同样会点空。
- **修正**（`src/app/canvas/renderer.ts`）：显示集合改为按需计算——由下一帧或一次命中检测触发，谁先到谁算；按状态、相机、画布尺寸和是否在导航缓存，绘制与命中共用。导航中沿用开始时带半屏外扩的集合（与原来相同）。
- **自查中发现并改掉的回归**：缓存最初只按相机和尺寸判断；而导航结束时会用同一个相机对象、以「非导航」再应用一次，于是导航中省略细节（普通节点、槽位、路口）的集合会被沿用，停下后细节仍不显示、也点不中。缓存加入「是否在导航」后恢复原行为。
- **验证**（新增到 P2a 的 e2e）：
  - 把 `requestAnimationFrame` 换成空函数（一帧也不画），打开地图后点击仍选中建筑。把命中检测改回「上一帧的集合」时这条失败，说明根因判断正确；
  - 显示普通节点，滚轮缩放，等相机停下后点击普通节点，选中的是节点而不是经过它的道路。去掉缓存里的「是否在导航」时这条失败（选中了道路）；
  - 按独立审查的要求补两条，守住缓存里的相机与画布尺寸：放大后定位到主路（远处厂房被裁掉），按 F 适应地图后点击远处厂房，应选中；放大并平移使厂房在画布右边界外 150 px，收起属性栏使画布变宽，点击厂房应选中。去掉相机比较、去掉宽高比较时各自对应的一条失败。
- **审查**：独立审查「修正后通过」，确认修法与原「每个非导航帧都重算」等价（缓存条件覆盖 `selectDisplay` 的全部输入，相机每次变化都是新对象），换地图时旧集合用不到；在韩华 TIF 上用精确覆盖率统计，新旧构建在打开、悬停、平移、滚轮、点击各阶段的显示集合与命中检测调用次数完全相同，悬停与平移的帧耗时差别在运行波动内。

## 设计决定

- 逐字段提交而不是整张表单一次应用：修改一处就是一步撤销，不需要未应用输入保护。未提交的输入只存在于正在编辑的那个输入框里：离开输入框即提交（包括点画布或目录选另一个对象时）；打开另一张地图时丢弃。代价是离开输入框就会提交；误输入可以撤销，输入无效时自动恢复原值。
- 只处理用户输入过的字段，未输入的字段不解析、不比较。属性栏每条命令只带一个字段，隐藏值、非零 Z、全精度浮点、扩展字段和未修剪的说明都不受影响（旧版 UX02 的要求，由内核的稀疏补丁保证，单测在内核上验证）。
- 数值用文本框（`inputmode=decimal`），不用浏览器的数字框：数字框在内容无效时读到空串，会与「清空改为未知」混淆。
- 高级地图上能预先判断的拒绝（转向规则与方向、规划数据与作业类型、非平面 Z）在界面上就不提供；其他拒绝（例如节点移动后入口需要重新定位、路带与新建筑冲突）属于结果校验，只能在提交时由内核判断，提示给出第一条错误。
- 入口的所属建筑与节点、作业点的归属与到达方式、道路反转按钮、转向规则的编辑、形状点的数值编辑、建筑与区域的分类放在 P3（业务对象、拓扑与分类），这里只读显示。

  - 地图名称不能为空；节点 X 坐标（无效输入、提交后显示规整值——包括显示字符串不变的情况、存全精度）；建筑兼容类型在 0.2 地图上没有「建筑」；建筑高度的来源；区域通行声明；
  - 锁定道路图层与只读地图：没有输入框和选择框。
- 变异检验（每次改动后恢复并校验哈希；列出的是实际被变异的位置）：
  - 物理参数字段：提交后仍视为「输入过」、去掉组字保护、选回原状态时提交——都会使测试失败；
  - 文本字段：Esc 改为提交、提交后不清除「输入过」（用例：节点 X 输入 104.56789 按 Enter 后，焦点仍在输入框时应立即显示地图中的值 104.568）——都会使测试失败。审查者设想的后果（撤销后失焦把已撤销的值重新提交）实际不会出现：点工具栏按钮先让输入框失焦，失焦时文本与地图值相同即复位；这一变异可见的后果是提交后仍显示未规整的输入，以及失焦时多弹一次「内容没有变化」；
  - 地图概览不按地图区分实例、只读地图可编辑、不附带设计假设、按显示值重新解析、新数值继承旧来源、拒绝原因取第一条、忽略转向规则：都会使测试失败；
  - 复审修正的 4 处（批量对全部道路改为未知、不计提交次数、说明不修剪、作业类型从不固定）：都会使测试失败；
  - 另有一条变异存活：切换单位时清除「输入过」标记。查明它是冗余代码——打开单位选择框必然先让数值框失焦，失焦时已提交或恢复，所以已删去并在注释里写明原因。
- 性能：属性栏每次渲染道路时计算连续路段。对每条道路测量：韩华 v02（428 条）中位数 0.19 ms、最大 1.5 ms；韩华 v01 最大 3.1 ms；中集 v02 最大 0.2 ms；审查者在韩华 TIF（688 条）上满载测得中位数 0.40 ms、最大 2.17 ms。转向规则、规划泊位、来源引用数都按地图快照只计算一次。
- 开发中测试抓到一个真实缺陷：按 Enter 提交后输入框仍有焦点，原实现以「是否有焦点」判断能否用地图值刷新字段，于是切换单位后仍显示旧单位下的数；此时离开输入框会把它按新单位提交（100.5 t 变成 100.5 kg）。改为以「输入过且未提交」判断：提交成功后立即回到可刷新状态，切换单位时按地图值重新显示。

## 已知限制

- 对象名称可以清空（格式只要求地图名称非空，`metadata.name` 的 `minLength: 1`），属性栏不另加限制。
- 每次提交新数值都新建一条设计假设来源（内核规则，与旧版相同），来源列表会随编辑增长；同名来源已能区分，但没有合并或清理。
- 结果校验类的拒绝（节点移动后入口需要重新定位、路带与新建筑冲突等）只能在提交时得知；审查者实测韩华 TIF 上节点 X 修改 79 次被拒，主要原因是入口需要重新定位（P3 的轮廓与入口修复处理）。
- 单位偏好保存在浏览器本地；P4 工程保存后改为随工程保存。
- 作业类型的第三条规划规则没有预判：停车区里、没有泊位引用的作业点改为「停车」会被内核拒绝，提示里夹有英文（`planning.ts` 的停车泊位检查）。现有真实地图没有停车区。
- 批量方向的转向规则判断只有探针核对，没有自动测试（需要带路口与转向规则的夹具，P3 做转向矩阵时补）。
