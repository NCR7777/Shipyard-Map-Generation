## 性能验收（同机、同脚本、交替背靠背）

- 脚本 `tests/perf/compare.perf.ts`，命令 `npm run perf:compare`。两边都是生产构建：studio 为本工作区构建；map 为 `../map` 提交 555789e，用 `vite build ../map --outDir` 构建到本目录缓存。
- 测量对象：韩华海洋造船厂地图，去掉底图，1600×1000 视口。
- 单位 ms，帧间隔受 240 Hz 刷新率量化（4.2 ms 一档）。以下为第一轮审查修正后的最终构建。

| | 平移 p50 | 平移 p95 | 平移最大 | 缩放 p50 | 缩放 p95 | 缩放最大 |
| --- | --- | --- | --- | --- | --- | --- |
| ../map（4 轮） | 8.4 / 8.4 / 8.4 / 8.4 | 20.8 / 24.9 / 20.8 / 20.8 | 58.4 / 70.9 / 66.7 / 62.5 | 4.2 / 4.3 / 8.3 / 4.2 | 29.2 / 25.0 / 25.0 / 25.0 | 33.3 / 29.2 / 33.4 / 29.2 |
| map-studio（4 轮） | 4.2 / 4.2 / 4.2 / 4.2 | 8.3 / 8.3 / 8.3 / 8.4 | 8.4 / 8.4 / 8.4 / 8.4 | 4.2 / 4.2 / 4.2 / 4.2 | 4.3 / 4.3 / 4.2 / 4.2 | 12.5 / 12.4 / 16.7 / 16.8 |

结论：每一轮、每一项都不劣于 `../map`，平移逐帧跟上刷新。

第二轮复审用同一构建独立重跑 4 轮：studio 平移 p50 4.2、p95 4.3；map 平移 p50 4.3–8.3、p95 12.5–12.6。map 的数字比上表好，说明本机状态会漂移，所以只比较背靠背交替的数据。第二轮之后的改动都不在画布绘制路径上（检查器、搜索排序、提示条与控件位置），没有重跑性能对比。

过程记录：

1. 第一版平移 p50 在 8.4 与 12.5 之间摆动。
2. 用关闭单项的构建变体定位：关掉道路带或屏幕层即可降到 8.3，关掉虚线或网格没有影响；JS 记录耗时每帧不到 0.6 ms。
3. 结论：瓶颈在 GPU 端的路径细分——一条合并的超大路径每帧都要重新细分，多圆路径也失去单圆快速路径。
4. 改为「道路每条独立路径」加「圆点贴图」后稳定在 8.3；审查后建筑与区域也改为每个一条路径，平移进一步降到 4.2。
