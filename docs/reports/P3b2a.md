日期：2026-09-26。执行者：主会话。前置：P3f4 已通过，本地提交 d9317ea，已推送 Shipyard-Map-Generation main 5e3701b（本地 `publish/map-studio-20260926`）。审查：RV27「修正后通过」（1 项重要、11 项次要）→ 增量复审「修正后通过」（新的 1 项重要、2 项次要，提交前已改，审查者认定不需再审）。

## 来由

- 用户 2026-09-26 在 P3f4 的选择题中自填：「我是要拆开之后自己在页面中重新连接，保持原有道路不变，然后我自己重新添加入口进行连接」；随后说「继续下一步」。
- P3f4 审查（RV26）在 4 张 EA01 复杂地图上逐步试了这套流程：拆出入口、从入口画路回路口、加新入口都能做；最后一步「把作业点关联到入口」18/18 被内核拒绝（`OPERATION_DEPENDENCIES_UNSUPPORTED`），属性栏在任何地图上也没有这个字段。
- 因此把 PLAN 的 P3b2 拆为 a–e，先做 P3b2a 补上这一步。

## 改动

- 内核 `src/domain/commands.ts`：
  - 新增 `serviceAccessLinkSupport`：复杂地图上 `updateServicePoint` 改 `accessPointId` 时先后检查：
    - 设置关联时，作业点不属于建筑（区域的作业点、没有归属的草稿），或目标不是同一建筑的入口 → 拒绝（`SERVICE_ACCESS_LINK_OWNER`）；清空关联不看归属（没有归属的草稿也能清掉，区域作业点本就没有关联）；
    - 作业点有显式内部通道 → 拒绝（`SERVICE_ACCESS_LINK_INTERNAL`：通道从所关联的入口出发，改关联会改变通道起点）；
    - 第一版曾把「必须属于建筑」当作多余检查删掉，并把内部通道放在前面；审查指出区域作业点指向不存在的 ID 时会漏过检查、区域作业点有内部通道时会给出不对的理由，已恢复并调整顺序；
  - 复杂地图上允许修改的作业点字段直接加 `accessPointId`（名称、类型、`accessPointId`，经上述检查）；其他字段（节点、所属、到达方式）照旧拒绝，同时改 `accessPointId` 与节点也拒绝；
  - 改关联时新旧入口都算作受影响对象，与改所属建筑时新旧建筑的做法一致；
  - 简单地图上允许与否不变（原本就允许，由校验器兜底）；受影响对象多了新旧入口，这一处两类地图都生效（例如入口图层锁定时也不能改关联）；
  - 依据：节点代理作业点在自己的节点接入路网，`accessPointId` 不参与接路与路径检查（`serviceConnections.ts`、`pathPreview.ts` 只在内部通道时用它）；复制作业点时会连带所关联的入口、动入口时作业点算作受影响对象（`commands.ts` 的复制闭包与影响范围），改关联后这两处随之改变，这是关联的本意。资源只作用在作业点上（真实地图的入口上没有资源）；规划扩展、研究接入扩展、编译与适配器都不读作业点的 `accessPointId`（审查者核实）。
  - 来源：改关联不留来源记录，与简单地图上改关联、改作业点名称的既有做法一致（`accessPointId` 不是拓扑或几何字段）。拆出入口时新节点说明里「作业点……不再关联这个入口」一句，重新关联后就过时了；说明记的是拆出那一刻，不随后续编辑更新。
- 属性栏 `src/app/ui/Inspector.tsx`：建筑的作业点多一行「接入入口」：
  - 节点代理或未声明到达方式：下拉框，选项为「（不关联）」与本建筑的全部入口；选中即提交，一个撤销步骤（「关联入口」「解除入口关联」）；所关联入口的节点没有连着任何道路时提示「这个入口的节点还没有连着道路。节点代理作业点按自己的节点接入路网，不经过入口」（只看有没有连着路，不判断方向与可达，那是路径检查的事）；
  - 显式内部通道：只显示所关联的入口（可点击跳转）与说明「要改关联，先改到达方式」；
  - 区域的作业点不显示这一行。
- 删除被作业点关联的入口时，内核提示「请显式一并选择服务点」，照做会把作业点一起删掉。`src/app/state/properties.ts` 按作业点的到达方式改写拒绝说明（界面层改写，内核不动）：
  - 节点代理或未声明：「作业点「X」关联着要删除的入口：先在它的属性栏「接入入口」选「（不关联）」，或把它一并选中删除（作业点也会删除）」；
  - 显式内部通道：「作业点「X」关联着要删除的入口，它的显式内部通道从这个入口出发，不能单独解除关联；要删除这个入口，请把它一并选中删除（作业点也会删除）」。EA01 九张图上有作业点关联的入口 449 个，其中 284 个关联的是显式内部通道作业点（审查者统计）。
- `src/app/state/editOps.ts`：拆出入口的提示加「可在作业点属性栏「接入入口」重新关联」，让用户知道去哪里接回。
- `docs/PLAN.md`：P3b2 拆为 P3b2a–e，执行顺序同改；P3b2a 加验收；P3b2c 写回「内部通道作业点改入口要连同通道起点一并处理」并补上复杂地图的例外（只作分段的两路路口不算）；P3b2d 记下 `detachAccessPoint` 与新关联的冲突。`docs/reports/P3f4.md` 加后注说明「复杂地图」的例外。`README.md` 进度。
