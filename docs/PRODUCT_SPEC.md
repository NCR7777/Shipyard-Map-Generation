# 船厂空间布局编辑器：产品与数据契约

状态：待实现的工程需求，不是已完成设计的正确性证明。版本1.0，2026-09-09。

## 1. 产品定位

用户手工构建多套船厂地图，或在具有尺度依据的平面图/影像上描绘地图。工具输出框架无关的 JSON，使 Codex 可以直接修改数据来改变布局，后续二维运输仿真和三维展示读取同一份语义地图。

本项目支持“真实空间布局支撑的二维运输计算实验”。软件提供比例、几何、连通、来源与接口，不负责证明输入就是实测船厂，也不负责证明仿真结论已在现场有效。

原有业务CSV是可选的导入/绑定来源，不是权威几何。没有真实坐标的旧路网不能自动排列后冒充真实底图。导入后无法确定的空间信息标记待人工补充。

## 2. 首版边界

必须形成：米制地图编辑、来源/底图管理、稳定JSON、拓扑及几何校验、网络级路径检查、可复用的无界面接口。

暂不做：全量调度求解器、真实交通控制、严格长大构件连续扫掠、三维物理引擎、VR设备适配、多人协同账户系统、任意CAD格式解析、未经授权的在线影像下载。

不以“保留接口”为由构建插件市场、微服务、消息集群或空壳子系统。首版实现JSON与二维适配器，其余先给出明确接口、能力声明、测试夹具。

## 3. 默认工程结构

建议使用TypeScript严格模式、React、Vite、Konva/react-konva。若已有仓库具备等效栈，可复用并在ADR中记录。不依赖单文件HTML，不依赖运行时CDN。提供Windows可用的安装和本地HTTP启动说明。依赖版本以实际安装、测试后的锁文件为准。

推荐目录边界：

```text
src/
  domain/          # 类型、纯数据、领域命令、不变量
  geometry/        # 米制几何、坐标变换、标定
  topology/        # 显式连接、转向、引用图
  validation/      # 结构、几何、拓扑、发布配置校验
  compiler/        # 从静态图生成不可变仿真/路由输入
  editor/          # 工具状态机、选择、快捷键、撤销重做
  renderers/2d/    # Canvas/Konva投影，不拥有领域数据
  adapters/       # 文件、资源、CSV、外部协议
  workers/        # 可取消/可丢弃过期结果的计算任务
  ui/             # 面板、对话框、来源/检查器
schemas/
examples/
tests/unit/
tests/integration/
tests/e2e/
scripts/
docs/
```

不要求立刻建Monorepo。只要模块依赖边界清晰，未来可将纯核心提取成包。Python、Unity或其他引擎复用的是数据契约，不是强行复用浏览器运行时对象。

## 4. 领域数据与几何单一来源

### 4.1 文件角色

- map.json：静态几何、拓扑、资源定义、来源、布局属性，是主数据。
- scenario.json：固定地图引用、任务、车辆、日历、运行规则、假设与扰动，不包含另一套可编辑地图。
- replay.jsonl或版本化的运行结果文件：车辆状态、事件、资源占用，绑定地图内容摘要与场景版本。
- editor-state.json：当前视窗、选中项、图层显隐、标尺设置等；不决定通行或物理状态。
- assets/：底图、未来三维模型和其他二进制资源。

单独导出map.json必须足以恢复所有语义几何；缺少图片只能导致背景缺失，不得令道路/设施丢失。完整工程导出zip，包含map.json、资源及manifest。文件名扩展名可为yard.zip，不自造不可查看的二进制格式。

### 4.2 顶层契约建议

M0依据以下结构产出真实JSON Schema、字段表、类型和一个最小合法示例；不得只留下此文字说明。

| 字段 | 语义 |
|---|---|
| schemaVersion | 文件结构版本，与软件版本和地图revision分离 |
| mapId | 布局的稳定标识；另存变体生成新mapId，并记录derivedFrom |
| revision | 文档修订信息；不是判断内容相同的唯一依据 |
| metadata | 中文名称、描述、layoutBasis、适用范围、审查记录 |
| coordinateFrame | 本地坐标、单位、轴向、可选地理锚定信息 |
| siteBoundary | 厂区或本次研究区域边界，允许孔洞 |
| nodes | 按稳定ID索引的节点位置与节点类别 |
| roads | 端点引用、内部折点、道路属性及资源关联 |
| junctions | 路口空间/节点组及其模型方式，不能隐含全部独占 |
| movements | 入弧—出弧允许关系、可选内部路径、冲突资源 |
| facilities | 厂房、总组区、坞区等边界、用途、出入口引用、可选高度 |
| accessPoints | 设施出入口或交接点与网络节点的明确关联 |
| servicePoints | 装卸/泊位/车位等服务位置、网络接入及资源关联 |
| zones | 可通行区、禁入区、水域、缓冲/候停区等独立区域 |
| resources | 路段、路口冲突区、车位、装卸位等容量资源定义 |
| sources | 底图、图纸、人工依据和字段来源记录 |
| assets | 二进制资源索引、相对路径、摘要及媒体类型 |
| backgroundLayers | 底图资源及像素到世界坐标变换 |
| extensions | 有命名空间的未来扩展；原样保留，不静默丢弃 |

可以根据验证过的需求调整字段组织，但不得删除这些概念所需的表达能力。核心字段严格校验，扩展只进入声明的命名空间。拓扑与资源未知时允许草稿，但不能无条件发布。

### 4.3 坐标与单位

权威坐标是本地右手笛卡尔坐标。XY为地面，Z向上，长度m、质量kg、时间s、角度rad；平面朝向从+X起逆时针测量。保存Vec3=[x,y,z]，普通二维地图默认地面z=0；z=0仅表示选择的本地基面，不代表测得海拔。

屏幕像素Y向下，由worldToScreen/screenToWorld负责转换。缩放、旋转视图和窗口尺寸不允许改变物理尺寸。地理锚点可空；为空时坐标仅为本地工程坐标，不要把+X/+Y无依据标成正东/正北。

可选地理信息记录原始CRS、坐标顺序、原点和旋转/投影方法。未实现并验证的地理转换不能用于声称标准GeoJSON导出。RFC7946 GeoJSON使用WGS84经纬度；本地米制文件可以使用类似点线面的结构，但名称和坐标约定必须明确，不冒充标准GeoJSON。

未来glTF/三维适配器显式转换轴向、单位、旋转和原点。若采用从本地Z-up到glTF Y-up的(x,y,z)->(x,z,-y)约定，必须同时转换对象姿态并测试基向量和往返；不能只交换高度字段。该约定是本项目选择，不要求其他引擎也用同样内部坐标。

### 4.4 ID、几何与派生属性

ID是稳定字符串，可具有node_、road_、facility_等可读前缀；显示名称与ID分离。采用按ID索引的字典，减少Codex修改导致的大范围数组变动。避免在对象内部重复保存与字典键冲突的ID。

节点位置是权威数据。道路保存fromNodeId、toNodeId、shapePoints（仅内部折点，按from到to顺序），中心线由端点位置+内部折点生成。道路长度每次按声明的2D/3D长度算法重新推导，不将可编辑lengthM当成另一套几何。

有来源的登记长度可以作为observedLengthM及sourceRef保存，用来比较误差，不能静默覆盖几何长度。道路包围盒、方向弧、显示网格、最短路缓存都是派生结果，携带mapContentHash及编译器版本。

道路可以有权威corridorPolygon；没有时，由中心线和声明宽度生成参考通行带，并标明derived/assumed。参考通行带不是已验证的扫掠安全空间。中心线变化后，人工通行带不得默默失效：更新、提示或阻止发布。

多边形必须定义外环/孔洞、闭合和方向约定，提供一致的规范化。平移/旋转/缩放提交后烘焙到权威坐标，不保留可与坐标矛盾的隐藏Canvas变换。不要因规范化改变顶点顺序语义或产生漂移。

accessPoint/servicePoint的位置优先引用专用网络节点；不要同时保留两套独立可编辑位置。设施的边界、入口和装卸位置是不同概念。整体移动设施需明确是否连同入口、服务点和附属设施移动，并以一个事务处理关联道路端点和校验。

### 4.5 未知与来源

对宽度、高度、载荷限制、速度及容量等数值明确设计Known/Unknown/Unrestricted/NotApplicable语义，或使用等价、可校验的判别联合类型。null仅表示未知；0不能表示未知或无限制。

每个对象至少有来源类别；关键几何/物理属性可细化到字段来源。来源可为surveyed、drawing、imagery_derived、design_assumption、synthetic、unknown，语义须在字段表中明确。地图整体basis建议conceptual/synthetic/reference_based/surveyed，不能因用户上传图片或校验通过自动升级。

可以提供命名的参考参数配置，但所有补值进入显式assumptionProfile并在导出与编译中保留。未知字段不得为了消除报错被自动填成40米、5km/h、容量1或无穷大。

## 5. 地图交互

布局：左侧对象/绘制工具与图层，中间二维画布，右侧属性/来源/引用面板，底部坐标、长度、错误计数和任务状态。界面中文、字段/代码使用稳定英文名称。

基础操作：平移缩放、适应地图、框选/多选、拖动、复制、删除、折线与多边形绘制、顶点增删移动、网格/节点/边投影吸附、量距/量面积、键盘数值输入、锁定/隐藏图层。快捷键在文本输入聚焦时不能抢走输入框的撤销或删除。

选择与移动的命中容差可用屏幕像素定义；几何计算/发布校验的容差必须用世界米制定义并保存为验证配置。两者不得混用。

道路吸附到边中间时，显示“创建节点并拆分道路”的明确操作。道路交叉时询问平交连接、不同层级、明确不连接或暂未处理；不自动生成连接。平交尚未处理可作为草稿，但不得通过严格发布检查。立体交叉只有显式标记和对应高程/层级信息才允许不连通。

拆分道路后原有出入方向、限制、资源和业务引用必须正确继承或生成需要人工处理的清单。节点合并同样需预览受影响对象。删除被引用对象默认拒绝并显示依赖；级联删除必须用户明确确认且可撤销。

实体模板只提供结构，不暗示实际工厂。至少提供厂房、堆场、总组区、坞区/码头、道路、入口、装卸位、候停/缓冲区、不可通行障碍的绘制/属性入口。

## 6. 底图导入与尺度依据

首版支持本地PNG/JPEG/WebP。可调不透明度、平移、旋转、锁定。SVG/任意CAD解析不列入首版。未经授权不上传或自动抓取在线影像。

最低标定方式：在图上选两点并输入真实距离，设置本地原点和方向，形成二维相似变换。两点距离只确定比例，不能证明整幅图没有非均匀畸变，也不能单凭它确定地理坐标。

增强方式：输入至少三个非共线控制点进行仿射配准，显示退化/病态警告与残差；三个点的零拟合残差不作为精度验证。需要独立检查点或多余控制点才能报告有意义的核验误差。未知精度标未知。

保存原始资源摘要、图片尺寸、像素坐标约定、控制点、imageToWorld矩阵、方法、资料日期和来源。图像解码/EXIF方向规范化必须与控制点像素坐标一致。修改背景标定后，默认只变底图；若要连同描绘对象变换，必须预览并事务确认，不能无意缩放全部已确认几何。

底图缺失时允许重新绑定，检查摘要和尺寸；不因同名就认定同一张图。导出zip时打包资源；单JSON导出明确提示不包含底图资源。

## 7. 网络与资源语义

道路是物理连接及形状，编译器将其产生一个或两个方向弧。双向道路的两条弧需要能引用同一个物理容量资源，否则不能表达双向互斥。道路方向可以unknown/forward/backward/both，unknown只能进入草稿或显式假设配置。

路口转向使用incomingArc/outgoingArc引用并可带内部折线。路线查询必须考虑转向状态，不能在普通节点最短路完成后才发现转向不合法。未知转向可以在基础示意预览中提示，但正式网络输出必须明确采用何种转向配置。

资源定义与图形分开：资源有类型、容量单位、容量值、作用对象集合和控制模型。允许exclusive、shared_capacity、directional_exclusive等声明，但首版只执行真正实现并测试的模型；其他模型应声明unsupported。面积不自动推导车辆容量。

不能将图中心的一个聚合节点自动解释为整片区域单车独占。单个路口可有多个冲突区，不冲突的通行可由不同资源表达。简单整路口独占可以作为用户明确选择的保守配置，但要标注假设。

水域、固定障碍和建筑默认按明确passability规则处理；厂房入口/内部通道需要显式授权几何，不能让路线从建筑中心穿过，也不能把所有进入厂房的合法运输无条件判错。

候停、缓冲和装卸位置应有服务位置及资源引用。没有定义的空地不能自动成为停车场。资源开放时间、动态故障和封路属于scenario/运行事件，不通过修改底图的颜色表达。

## 8. 版本化JSON与持久化

使用JSON Schema Draft2020-12或等效已验证版本，记录所采用版本。以Schema生成类型或建立Schema/类型一致性测试，避免两份规则漂移。JSON不包含注释、函数、DOM、浏览器File句柄或会话blob URL。

结构校验之外实现语义校验：ID/引用、单位、几何有效性、网络连通及资源完整性。核心未知字段应报错提示拼写，不静默忽略；命名空间扩展完整保留。不能识别的行为扩展必须阻止该能力的正式发布，而不是仅保留原文后假装支持。

采用确定性序列化：固定对象键顺序、2空格缩进、UTF-8、固定换行。顶点数组不排序；避免保存时不断舍入浮点坐标。空编辑导出不改变语义。内容摘要算法、排除字段（如编辑器相机和保存时间）及规范化规则写入文档。

每个有效保存可更新revision，但外部Codex可能忘改revision，因此判断缓存失效和运行绑定以内容摘要为准。可选执行map:normalize统一格式，不擅自修复几何。

导入在临时文档中完成解析/迁移/校验，成功后再替换当前模型；错误可打开隔离的只读检查，不污染当前有效状态。打开未来版本默认只读或拒绝，不能导出缩水版本。迁移保留原件和差异。

本地IndexedDB可作自动恢复草稿，不是唯一权威副本。JSON导入和下载是跨浏览器基线；支持时用File System Access增强打开/保存，必须请求权限。外部文件更改不能假设一定有浏览器文件监听，至少实现显式重新载入和覆盖前检查；权限不可用时另存为并说明限制。

zip导入限制文件数、单文件大小、解压总量和压缩比，拒绝绝对路径、..路径穿越及不在白名单的可执行内容。标签作为文本渲染，不把JSON字段直接注入HTML。

## 9. 校验与发布配置

输出至少包括severity、code、entityType、entityId、jsonPath、message、suggestedAction、location，可定位到画布对象。建议分为：结构错误、几何错误、拓扑问题、来源/尺度警告、假设/未支持能力。

必须检查：非有限数值、非法/重复键或ID、悬空引用、零长度道路、未闭合/自交多边形、未明确的平交、错误方向/转向、服务入口未接入网络、未授权穿越水域或障碍、主几何与派生值不一致、引用未支持资源类型、缺失必要资产/来源、业务绑定目标失效。

地图不必全图强连通。应根据研究范围、方向和设施服务要求检查指定OD的可达性，并报告不可达原因。辅助孤立区可以存在，但需显式标注，不静默接受主要装卸点断开。

发布配置分级：
- draft：允许缺信息，始终可保存带问题的草稿。
- topology_preview：要求可解析、引用和基础拓扑有效，输出“拓扑可达/不可达”，不能称安全可通行。
- level2_network：尺度明确、设施入口/路网/规则可解释，必要物理参数已知或有显式假设，所有使用的能力受支持；输出网络级条件可行性。
- swept_geometry：后续能力，首版不支持。不能因为给了货件宽高就通过此级。

已按比例设计的synthetic地图可以通过level2_network的结构/配置检查，但仍然是synthetic，不变成reference_based或surveyed。

## 10. 无界面接口

接口职责应稳定，名称可在M0统一后确定：

```ts
parseMap(text): ParseResult;
validateMap(map, validationProfile): ValidationReport;
applyMapCommand(map, command): CommandResult; // 原子性，返回变更与撤销信息
compileNetwork(map, compileProfile): CompileResult;
findRoute(compiled, routeQuery): RouteResult;
validateBindings(map, bindings): BindingReport;
toSceneSnapshot(map): SceneSnapshot;
```

RouteResult明确distances、freeFlowTime、appliedAssumptions、missingChecks和地图摘要。不支持的资源占用调度或载荷转弯验证必须显式列入missingChecks，不给“安全路线”标签。

外部SimulationAdapter输入：不可变编译地图、独立scenario和版本；输出状态/事件流，不直接改map.json。状态最少携带mapId/mapContentHash、entityId、sequence、simulationTime与pose。为研究迟报/乱序预留occurredAt与observedAt，不能将未来事件提前注入可见状态。首版只需文档和模拟消息夹具，不建设真实消息服务器。

RenderAdapter消费SceneSnapshot与可选运行状态，不拥有交通规则。未来Three.js/Unity/VR按同一稳定ID建立对象绑定，三维模型附加assetId和局部姿态；glTF是表现层资产，不替代道路连接、资源和来源语义。

提供CLI：map:validate、map:compile（实现编译后）、可选map:normalize/map:diff。无需浏览器和Canvas即可运行。给Python提供编译后JSON样例和读取契约；SUMO/GeoJSON/三维导出在未实现前明确unsupported。

## 11. 路径预览的能力边界

二维预览用于检查连通、方向、显式转向及已定义的静态尺寸/重量限制。100m道路以2m/s预览应为50s自由流时间。运行时间由仿真时钟决定，渲染帧率不决定车辆物理速度。

矩形车辆沿中心线运动只作网络与时间展示，不声称经过连续碰撞或转弯检查。多车调度未实现时，不因画面上互不相撞就报告资源安全。

地图编辑后清除或重编译当前预览；历史回放仍引用其原始地图快照，不能在新图上无提示播放旧结果。

## 12. 扩展至三维与VR

首版保留z、可选heightM、实体类型、局部姿态、资产引用、稳定ID和坐标变换接口。未知建筑高度不能填成“实测10m”；简单拉伸预览可选显式展示假设，不写回实测字段。

后续先做无VR的三维只读查看器：读取同一map.json，执行坐标适配，建筑/道路对应稳定实体ID。二维和三维测距必须一致。之后再接运行状态、交互控制和VR输入。

VR交互产生的修改或指令应进入同一领域命令/仿真接口，不绕过校验。渲染循环和仿真步进解耦，模型文件不与业务规则绑定。预留接口只降低重构成本，不承诺无需新增模型即可自动升级成完整数字孪生。

## 13. 例图、性能与交付

最终至少3个明确标为synthetic的完整例图：简单验证图、存在替代通路的布局、含共享瓶颈及明确候停区的布局。例图用于产品/回归验证，不作为实际船厂样本或算法优越性证据。另提供断开入口、非法路口、自交多边形等错误样例。

以正常笔记本和声明浏览器为目标，建立可复现规模测试（例如2000节点、4000道路、数百设施）。记录设备、浏览器、顶点数、加载/校验耗时和交互卡顿；规模是测试目标，不是未测的性能承诺。必要时空间索引和Worker优化，不提前上分布式系统。

最终交付：可本地运行的源代码、锁文件、Schema、字段/坐标文档、CLI、样例、自动化测试、使用说明、适配器契约、迁移规则和已知限制。功能清单区分implemented、documented_interface、unsupported，不以文档存在代替功能完成。
