# 建筑与区域分类、干船坞深度

建筑与区域是两类对象。建筑指厂房、仓库、办公楼、宿舍、动力站房等实体建筑；区域指干船坞、堆场、总组场地、码头作业区、水域、停车区等空间范围。详细分类分别设置，不能跨类混用。

## 使用

普通属性只显示“建筑分类”或“区域分类”。旧核心类型保留在折叠的“高级兼容类型”中；绘图时旧类型在“高级绘图兼容类型”中，不与日常分类并列。

- 用“建筑”画楼、厂房等建筑轮廓，选中后在“建筑分类”设置用途。
- 用“区域”画干船坞、堆场等范围，选中后在“区域分类”设置用途。沿用矩形、三点斜矩形和多边形绘制、编辑。
- 干船坞选择区域类别“干船坞”，填写“干船坞深度 (m)”和“深度参照面”。深度表示从注明的参照面向下至坞底的结构深度；不等同于水深。留空表示未知。
- 深度选择已有来源，或明确使用“本次设计假设”。测试或假设数值不升级成现场实测数据。深度不写入建筑高度，不自动移动边界 Z。
- 左侧“建筑与区域分类”分别设置新建筑、新区域默认分类，并新增或改名自定义分类。每个自定义分类只属于建筑或区域之一。
- 创建对象及其默认分类是一个撤销事务。已存在对象的分类、深度和其他待应用属性一起提交；沿用保存、撤销、重做和 JSON 导出。

用途分类不会自动改动区域基础类型、通行声明、道路、入口、作业点、资源容量或既有规划角色。需要时分别设置通行和连接。

旧地图曾将堆场、船坞、码头等存为 `facilities`。编辑器保留并标识这些旧设施记录；不会自行转换为 `zones`，也不会丢失其入口、储位、服务点和资源引用。新绘图按建筑和区域分别分类。

## 数据契约

复用已有版本化扩展机制，核心 map Schema 和冻结原件不变。命名空间：

```json
"org.shipyard.spatial_classification": {
  "version": "1.0",
  "category": "metadata"
}
```

地图根 `extensions[namespace].customClasses` 保存自定义目录，每项 `{ id, label, appliesTo }` 的 `appliesTo` 恰含一个 `facilities` 或 `zones`。稳定 ID 与显示名称分离；改名不重建对象引用。已引用类别不能被删除或改到另一对象类型。

实体 `extensions[namespace]` 保存分类。以下是**示例假设**，不是 CIMC 船坞的实测值：

```json
{
  "classId": "dry_dock",
  "depthM": { "state": "known", "value": 9.5, "sourceRef": "dock_depth_assumption" },
  "depthReference": "假设：从坞口地坪向下至坞底"
}
```

`dock_depth_assumption` 必须是 `sources` 中实际存在的来源。已知深度要求大于零的有限米制数值、明确参照面及来源；未知用 `{ "state": "unknown" }`。深度仅允许在区域上声明。改区域类别不静默清除已填深度。

版本 1.0 的输入校验覆盖目录、适用对象、分类引用、深度及来源。未知版本保留原始载荷，拒绝覆盖其分类数据。其他命名空间不改写。

原有 JSON 和 FAST01 编译导出保留目录、实体分类及来源；详细分类和深度不会改变路由弧。完整地图摘要包含这些编辑，所以此前外部调度结果仍按既有版本一致性规则变为旧结果。

FAST01 语义补丁仍只处理核心 `kind/name`，不能猜测深度；`unclassified.json` 仍按核心 `kind` 统计，填写详细分类并不等于自动修改核心类型。
