# 建筑与区域分类、干船坞深度

建筑与区域是两类绘图对象。建筑描厂房、仓库、办公楼、宿舍、动力站房等实体边界；区域描船坞、堆场、总组场地、码头作业区、水域、停车区等功能占地。两套详细分类分开设置，但建筑与区域的几何允许叠加；这不是物理上互斥的分类。

## 使用

普通属性只显示“建筑分类”或“区域分类”。旧核心类型保留在折叠的“高级兼容类型”中；绘图时旧类型在“高级绘图兼容类型”中，不与日常分类并列。

- 用“建筑”画楼、厂房等建筑轮廓，选中后在“建筑分类”设置用途。
- 用“区域”画干船坞、堆场等范围，选中后在“区域分类”设置用途。沿用矩形、三点斜矩形和多边形绘制、编辑。
- 确认为岸上抽排水坞池时选择区域类别“岸式干船坞”；不确定时选择“船坞（类型待确认）”。浮船坞选择“浮船坞（当前占位）”，区域仅记录当前平面占位。
- “干船坞深度 (m)”表示从注明参照面向下至坞底的结构深度，留空为未知；不等同于坞口水深或允许吃水，不能据此推算船舶可进坞能力。切换分类不换算、不清空原值，其他区域已有深度仍保留显示。
- 深度选择已有来源，或明确使用“本次设计假设”。测试或假设数值不升级成现场实测数据。深度不写入建筑高度，不自动移动边界 Z。
- 左侧“建筑与区域分类”分别设置新建筑、新区域默认分类，并新增或改名自定义分类。每个自定义分类只属于建筑或区域之一。
- 创建对象及其默认分类是一个撤销事务。已存在对象的分类、深度和其他待应用属性一起提交；沿用保存、撤销、重做和 JSON 导出。

用途分类不会自动改动区域基础类型、通行声明、道路、入口、作业点、资源容量或既有规划角色。需要时分别设置通行和连接。

旧地图曾将堆场、船坞、码头等存为 `facilities`。编辑器保留并标识这些旧设施记录；不会自行转换为 `zones`，也不会丢失其入口、储位、服务点和资源引用。新绘图按建筑和区域分别分类。

## 船坞术语与描绘范围

| 区域分类 | 稳定 ID | 此编辑器中的含义 |
| --- | --- | --- |
| 船坞（类型待确认） | `dock_unspecified` | 已确认是船坞，但尚无充分资料区分岸式或浮式。 |
| 岸式干船坞 | `dry_dock` | 岸上的坞池，通过进水、关闭坞门及抽排水完成进出坞和干态作业。 |
| 浮船坞（当前占位） | `floating_dock` | 通过压载水调节升沉的浮式设备；所画区域只记当前平面占位。 |

岸式坞池与浮船坞的区别依据结构和工作方式，不能只依据影像中是否看见水判断。上述术语参照 [OSHA 的干坞作业说明](https://www.osha.gov/ship-building-repair/dry-docking)。

建筑层记录楼、厂房等实体边界，区域层记录功能占地。现实中厂房可以覆盖干船坞，因此允许在同一位置分别描建筑和船坞区域；[英国船厂资料第 6.5 节](https://www.gov.uk/guidance/rating-manual-section-6-part-3-valuation-of-all-property-classes/shipbuilding-yards#buildings)给出了覆盖式建造坞的例子。

`depthM` 的含义始终是“注明参照面至坞底的向下结构深度”。坞口水深还涉及坞槛及水位基准；[同一资料第 6.9 节](https://www.gov.uk/guidance/rating-manual-section-6-part-3-valuation-of-all-property-classes/shipbuilding-yards#dry-docks)采用了特定潮位下坞槛上方的水深，不能与本字段直接互换。本编辑器不据结构深度推算允许吃水、浮船坞升沉状态或承载能力。

已有 `dry_dock` ID 和深度声明原样保留，只澄清显示名称；不自动迁移旧图或重新判定船坞类型。新分类也不改变核心 Schema、边界 Z、通行声明和路由。

## 数据契约

复用已有版本化扩展机制，核心 map Schema 和冻结原件不变。命名空间：

```json
"org.shipyard.spatial_classification": {
  "version": "1.0",
  "category": "metadata"
}
```

地图根 `extensions[namespace].customClasses` 保存自定义目录，每项 `{ id, label, appliesTo }` 的 `appliesTo` 恰含一个 `facilities` 或 `zones`。稳定 ID 与显示名称分离；改名不重建对象引用。已引用类别不能被删除或改到另一对象类型。

实体 `extensions[namespace]` 保存分类。以下是**示例假设**，不是 CIMC 船坞的实测值：

```json
{
  "classId": "dry_dock",
  "depthM": { "state": "known", "value": 9.5, "sourceRef": "dock_depth_assumption" },
  "depthReference": "假设：从坞口地坪向下至坞底"
}
```

`dock_depth_assumption` 必须是 `sources` 中实际存在的来源。已知深度要求大于零的有限米制数值、明确参照面及来源；未知用 `{ "state": "unknown" }`。深度仅允许在区域上声明。改区域类别不静默清除已填深度。

版本 1.0 的输入校验覆盖目录、适用对象、分类引用、深度及来源。未知版本保留原始载荷，拒绝覆盖其分类数据。其他命名空间不改写。

原有 JSON 和 FAST01 编译导出保留目录、实体分类及来源；详细分类和深度不会改变路由弧。完整地图摘要包含这些编辑，所以此前外部调度结果仍按既有版本一致性规则变为旧结果。

FAST01 语义补丁仍只处理核心 `kind/name`，不能猜测深度；`unclassified.json` 仍按核心 `kind` 统计，填写详细分类并不等于自动修改核心类型。

## 分类颜色（2026-09-16 增补）

- 分类决定填充色和普通边框色；选中只强调边框，保持类别填充色。建筑与区域仍分别使用已有填充不透明度，0% 时保留边框和点击命中。
- 左侧“分类颜色图例”按建筑、区域列出当前地图已有的类别和数量；新对象默认分类、对象属性旁显示对应色块。
- 内置类别使用固定颜色，例如生产厂房橙色、仓库紫色、办公楼蓝色、堆场绿色、岸式干船坞蓝色、浮船坞紫灰色。自定义类别按稳定 ID 派生颜色，改名、增添其他分类及保存恢复不会换色；较多类别仍应结合文字图例辨认。
- 旧地图未填写详细分类时，依据已有基础类型着色并注明“未设置详细分类”。旧 `dock` 仅显示待确认船坞色，不能由此判成干船坞；未知分类扩展按基础类型显示并明确标记未识别。
- 颜色只存在于派生显示场景，不向地图 JSON 新增颜色字段、存储或历史。颜色不代表通行、承载或工程核验状态，也不改变几何、连接、路由或既有规划角色。场景沿用地图变更缓存，图例按场景数组缓存，不逐帧全图校验。
