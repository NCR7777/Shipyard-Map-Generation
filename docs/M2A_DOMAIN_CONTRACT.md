# M2A 领域核心契约

本文件描述已实现的领域命令、校验和场景投影，不以核心代码存在代表 M2A 界面或浏览器验收通过。实际运行结果另见本轮阶段报告。

## 兼容方案与几何来源

继续使用 `schemaVersion: 0.1.0`、既有 JSON Schema 及其生成类型。设施、区域、出入口、服务点和道路物理值已由原 Schema 定义，此次没有另建 `buildings`、`canvasShapes` 或另一套画布地图，也未手改生成类型。已有 M1 点线地图保持可加载。

原 M1 对多边形仅做结构检查；M2A 开始检查闭合、绕序、自交及孔洞。因此以前可作为未检查数据保留的非法多边形，现在会被共同导入路径拒绝，并定位到相应字段。原文件和当前编辑不会被自动修复或覆盖。结构版本不变表示字段结构兼容，不表示旧文件绕过新增加的几何检查。

世界坐标仍为米制右手 XY 平面，Z 向上。平移和绕 Z 轴旋转直接更新权威节点或多边形顶点；没有另一份可编辑的 Canvas 旋转角或缩放值。设施面积、显示颜色与中心点不产生入口、服务点、通行容量或道路连接。

## 选择、移动和旋转

`Selection` 保留必需的 `nodes`、`roads` 字段，并添加可选的 `facilities`、`zones`、`accessPoints`、`servicePoints`。`normalizeSelection` 返回去重、按 ID 排序的六类 `FullSelection`。旧点线调用者可以保持原选择对象结构。

`translateSelection` 使用 `delta: Vec3`；`rotateSelection` 使用 `pivot: Vec3` 和 `angleRad`，XY 绕给定中心逆时针旋转、Z 不变。有设施被选中时，命令必须明确提供以下策略，否则事务拒绝：

- `boundaryOnly`：仅移动/旋转设施多边形；未显式选择的关联节点保持原位。
- `withAssociatedNodes`：同时移动设施列出的入口、服务点所引用的节点。共享节点只处理一次，相邻道路端点由该节点自动派生。

显式选择道路包含其端点节点及内部折点；显式选择入口或服务点包含其 `nodeId` 节点。独立选择区域只变换区域边界。多边形的全部孔洞与外环采用相同变换。

`selectionImpact(map, selection, policy)` 返回实际移动闭包、受影响道路 ID 和共享道路节点 ID，供界面展示与拖动预览。预览不提交领域修改，拖动结束由一个领域命令形成一个撤销事务。回滚和重做保存完整前后地图，复用已分配的 ID。

## 点关联和设施成员

`accessPoints` 和 `servicePoints` 只通过 `nodeId` 使用权威坐标，不增加独立的 `position`。新增/更新点命令可同时提供 `{ id, node }` 新节点，节点 ID 必须与点的 `nodeId` 一致；同一事务全部校验成功后才提交。

入口的 `facilityId` 与设施的 `accessPointIds` 双向维护；带设施归属的服务点与 `servicePointIds` 双向维护。只改点的名称或节点时不重排设施成员数组。设施普通属性补丁不允许直接改成员列表。

服务点更新使用 `facilityId: null` 或 `accessPointId: null` 显式删除可选关联；最终 JSON 省略该可选字段，不写入不符合 Schema 的 null。重绑入口至另一设施时，若已有服务点仍声明与其冲突的设施，事务拒绝；必须先显式处理服务点关联。此阶段不根据设施中心自动生成任何点。

## 复制与删除闭包

`closureSelection` 返回复制闭包：设施及其成员点、这些点所用节点、选中道路的端点、选中服务点所引用的入口。它不会因入口节点连接外部道路就复制整张路网。

`duplicateSelection` 必须提供恰好覆盖闭包、全图唯一的新 ID 映射和明确米制偏移。设施副本的成员、入口、服务点及节点全部重映射；与原设施相接的外部道路保留在原位置，不连到副本。只有点被单独复制而设施未复制时，必须明确提供 `associationPolicy: 'retainFacility'` 才允许将新点加入原设施；默认拒绝猜测该外部归属。对象扩展可能含未知引用时拒绝复制。

删除有成员点的设施，必须指定 `facilityPolicy: 'withAssociatedPoints'`；否则拒绝。`orphanNodes: 'keep'` 保留成员节点；`deleteUnused` 仅清理已删除成员点的无剩余道路/点引用节点，共享路网节点仍保留。

用户显式选择删除的节点若仍被未删除道路、入口或服务点引用，事务拒绝并给出依赖路径。未被选中的服务点若仍引用被删入口，也拒绝。失败事务没有部分新增/删除、悬空引用或历史记录变化。

## 物理值与设计假设

`updateRoad` 扩展 `widthM`、`heightLimitM`、`massLimitKg`、`speedLimitMps` 属性补丁，保留四态 `known`、`unknown`、`unrestricted`、`not_applicable`。没有来源的新 known 值必须通过 `designAssumption: { id, name?, description? }` 明确创建来源，来源类别固定为 `design_assumption`，并同时绑定数值 `sourceRef` 与实体 `provenance.fieldSources`。它不会修改或冒用原有 surveyed 来源。

已经带有效 `sourceRef` 的值保留该来源。物理值按状态、数值/说明及来源字段比较；JSON 对象键顺序变化不会产生虚假修改或新增来源。旧文件中未经本次修改、没有来源的 known 值可保留草稿兼容性；软件不替它补成实测。known 改成其他状态时，清除对应 `fieldSources` 映射，保留历史 Source 实体。设施高度更新采用同样的来源规则。工厂函数默认未知高度、未知道路物理值和 synthetic 来源。

## 显式拆分道路

`splitRoad` 接收原道路 ID、从 from 端沿 XY 折线累计的 `distanceM`、两个新道路 ID 和切分节点 ID。切分位置由原道路几何派生，插值 Z；默认新建节点。`existingNode: true` 表示用户显式复用已有节点，已有位置必须在切分位置的 `1e-6 m` 三维容差内，且不是原端点。

切分里程距离两端均须大于 `1e-6 m`。拆分后两个新道路的水平长度之和与原道路之差不得大于 `1e-6 m`。新道路继承方向、物理属性及来源；内部折点按原顺序分配，原道路 ID 删除，不能将一个旧 ID 同时用于两段。

资源、转向、人工 corridor、登记长度以及未知扩展引用尚无完整重写能力，对这些语义采取拒绝/整图只读保护。普通绘图相交、近邻和重叠从不自动拆路或连接。

成功结果返回 `mapping: { oldRoadId, newRoadIds, nodeId }`，并在声明的 metadata 命名空间 `org.shipyard.editor.lineage` 中追加：

```json
{
  "version": "1.0.0",
  "roadSplits": [
    {
      "oldRoadId": "road_original",
      "newRoadIds": ["road_left", "road_right"],
      "nodeId": "node_split",
      "distanceM": 40,
      "originalLengthM": 100
    }
  ]
}
```

命名空间声明为 `version: '1.0.0'`、`category: 'metadata'`。已有同名不兼容声明、未知载荷或未知条目不覆盖。沿革 ID 是历史标识，不作为当前实体引用校验；后续复制/删除不改写历史沿革，撤销拆分则恢复完整先前地图。

## 有界多边形校验与投影

多边形外环和孔洞必须显式闭合，首尾 XYZ 完全相同；外环逆时针、孔洞顺时针。检查容差为 `1e-7 m`，检查零长边、重复顶点、相邻边折返重叠、非相邻边相交/接触、零面积、非平面坐标、孔洞越界、外环接触和孔洞相交/嵌套。

当前上限为单多边形含闭合点共 512 顶点、16 孔洞；整图多边形共 8192 顶点；XY 绝对坐标不超过 `1e9 m`。超过范围明确报错，不返回未检查的成功。单多边形最多报告 200 个错误，避免畸形输入产生无界诊断。没有实现任意曲面、曲线、几何布尔运算或测绘级精度保证。

节点近邻提示阈值为 `0.5 m`，只作未连接提示。检查最多 2000 节点，节点—道路线段组合最多 2000000，最多输出 100 条近邻提示；超限显示检查范围限制，不以无警告证明拓扑完善。它不是交叉道路分类或转向可达性检查。

`SceneSnapshot` 增加设施、区域、入口和服务点数组；设施与区域边界完整深拷贝，点位置只由节点派生，包围盒包含多边形外环和孔洞。场景投影、命令、几何及校验仍可在无 DOM/Canvas 环境运行，框架依赖留在二维适配器。

## 明确未实现的能力

底图、资产资源读取、路口转向和容量资源、地理锚定、人工道路边界编辑及未知行为扩展继续受保护。没有执行车辆扫掠、运动学转弯、净空/承载认证、建筑/水域通行检测或完整网络路径编译；仍只提供 draft 校验，不把地图有效称为运输安全或 simulation-ready。

本阶段文档不声称已经完成 M2B 的底图标定/ZIP，也不声称已实现三维、VR、复杂调度或车辆动画。
