# M1.1 本地文件写回：能力与手工验收

本文件区分已实现的适配器逻辑、自动化替身测试和原生系统对话框验收。任务书 S05、S07、S09 的原生文件部分不能仅用 mock 通过作结论。完整阶段结果由本轮阶段报告记录。

## 实现边界

`src/adapters/localFiles.ts` 的 `LocalFileController` 只负责一个工程的本地文件关联和写回；它不改变领域地图、编辑历史、浏览器工程保存基线或 JSON 下载状态。未支持 `showOpenFilePicker` / `showSaveFilePicker` 的环境返回 `unsupported`，仍可使用浏览器保存、普通文件导入及 JSON 导出。

授权选择器必须由用户点击直接触发。不能先等待数据库保存，再在同一次点击中调用文件选择器；异步等待可能失去浏览器要求的用户激活。原生接口须满足浏览器安全上下文和权限要求。[Chrome 官方文件系统文档](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)

打开或重新载入先读取受限大小的 UTF-8 内容，再复用 `loadMap` 的解析、校验、摘要与场景编译。候选只有在界面保护旧工程并确认替换后，才通过 `acceptOpen(token)` 成为文件读取基线。取消、权限拒绝、解析失败都不修改当前地图；旧关联与旧确认摘要保留。

重新聚焦检查、显式重新载入、写回前都读取文件。冲突判定使用原始字节 SHA-256，包含空白和 `revision`；只修改 JSON 格式也会被提示。显示的地图变更状态另用领域 `contentHash`，不会把这两个摘要混为一谈。

写回只有在可写流 `write()` 和 `close()` 都成功后才确认对应快照的文件保存基线。保存期间继续编辑产生的新内容不会被这一较早快照的成功结果标为已写回。原生流关闭是提交点，不能在下载发起或 `write()` 返回时提前声称文件已保存。[MDN createWritable 文档](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable)

检测到冲突时，当前有效的冲突 token 必须与写前重读的原字节摘要一致，才能执行明确覆盖；外部再次修改会使旧确认失效。无效 JSON、非法 UTF-8 或超限文件不能通过确认绕过保护，须修复原件或另存新文件。另存选中当前关联文件同样检查冲突；另一非空目标须是合法地图，选择后内容再变会拒绝写入。

文件句柄本轮仅存在于内存。刷新后显示“未关联”，需要重新选择/授权，不自动恢复磁盘访问。工程切换不能在本地文件操作尚未结束时清除或重用关联。无自动后台磁盘写回、文件监听器、目录工程或 ZIP 写回。

普通浏览器文件 API 不提供相对于 Codex 或其他桌面程序的原子比较写入。本实现可检测读取时已经发生的变更，不能保证写前读取至关闭之间绝无第三方修改；出现并发编辑时先保留浏览器恢复副本或另存新文件，避免两个应用同时保存同一目标。该限制不是实现了文件锁的声明。

## 自动化证据的含义

`tests/unit/M11_localFiles.test.ts` 使用内存 `FakeHandle` 和可控流。这些测试验证：能力检测、候选确认、取消/拒绝、共享校验错误、100m→120m 且 revision 不变的外改、原字节冲突、过期确认、非法外部内容保护、关闭后才确认、迟到成功摘要、各写入阶段失败、另存目标保护与工程关联隔离。

运行命令：

```powershell
./node_modules/.bin/vitest.cmd run tests/unit/M11_localFiles.test.ts
```

上述测试不调用原生授权对话框，不读取或覆盖真实用户文件，不证明 Chrome/Edge 的权限交互或物理磁盘已验收。最终测试数量与退出码以本轮报告和实际终端输出为准。

## 待执行的原生手工验收

使用受支持浏览器，通过本地 HTTP 启动应用；先把 `examples/M1_synthetic.map.json` 复制到专用临时目录，以下只操作该副本。不要直接使用研究原件。逐项记录浏览器版本、操作、结果及必要截图；此列表本身不是通过记录。

| 项目 | 操作 | 应观察到的结果 |
|---|---|---|
| N01 能力与授权 | 点击本地打开，先取消选择，再选择测试副本；在没有选择器能力的另一浏览器检查入口 | 取消保留地图、浏览器记录和文件关联；支持环境由系统对话框授权；不支持环境仍可浏览器保存、导入、导出 |
| N02 真实写回 | 授权打开 100m 样例，数值改为 110m，点击本地写回；完成后用文本编辑器打开该文件并运行 CLI | 写回成功后磁盘为 110m，ID 与引用不变，CLI 退出 0；保存状态明确对应本地文件 |
| N03 三目标独立 | 在 N02 后再改为 115m，浏览器保存，再导出 JSON，尚不点击本地写回 | 浏览器保存成功与已发起下载分别显示；原关联磁盘文件仍为 110m，本地状态仍有未写回变化；输入框 Ctrl/Cmd+S 不偷偷写回磁盘 |
| N04 外改重载 | 保持 revision 不变，用文本编辑器将磁盘端点改为 120m，切回应用；再显式重新载入 | 重新聚焦报告外部变化，不自动覆盖浏览器；共同导入校验通过并确认后才显示 120m、更新长度/图形/摘要；重载之前先保护当前工程版本 |
| N05 双侧冲突 | 磁盘改为 130m，浏览器改为 140m；分别检查取消、保存恢复副本后重载、另存新文件与明确覆盖流程 | 取消保留双方；恢复副本可在最近项目打开；另存不改原文件；明确覆盖有具体目标和确认。确认期间再外改为 150m 后，旧确认不得覆盖该新变化 |
| N06 无效外部内容 | 将测试磁盘文件改成悬空引用或不完整 JSON，重新载入及尝试覆盖 | 有结构化错误/具体路径；当前有效地图保留，原件未改，拒绝用覆盖确认绕过；仍可另存当前有效地图到新文件 |
| N07 拒绝与失败 | 拒绝浏览器写权限；取消另存选择；在浏览器提供的权限设置中撤销文件授权后再尝试写回 | 不显示写回成功，不推进文件确认摘要，不破坏当前地图；浏览器保存及导出仍可用。真实关闭失败若环境无法可靠触发，记为未手工验证，不能套用 mock 结论 |
| N08 刷新及多工程 | 授权打开工程 A，另建 B，再切换/刷新恢复 A | A/B 地图与浏览器记录不串用；本地句柄不跨工程误用，刷新后明确未关联，需要手动重新授权；操作进行中不会切项目导致迟到写回误关联 |
| N09 本地另存目标 | 选择新文件；再测试选择有无效内容的现存文件，以及已外改的原关联文件 | 新文件可写回；失败不替换此前关联。非法现存内容保留并提示换新文件名；已外改原关联文件仍出现冲突，不能用另存绕过 |

保存验收不包含跨应用原子锁、强制断电恢复、网络盘一致性、浏览器长期存储保留承诺或工程目录/ZIP。对应能力尚未实现时不能勾选为通过。
