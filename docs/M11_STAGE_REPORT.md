## 实现与使用

- **保存工程 / Ctrl/Cmd+S**：将已提交地图保存到浏览器 IndexedDB，保留明确保存版本及上一版本。快捷键在输入控件焦点下也进入应用；存在未应用输入时弹窗说明，可返回应用属性，或只保存已经提交的地图。文本撤销/删除仍属于输入框；弹窗按钮焦点下不会穿透修改背后的地图或文本。
- **自动草稿**：成功编辑后 600ms 防抖；恢复完成前禁止自动写入空地图。地图正文、确认摘要、独立存储版本与视窗记录分开。保存期间继续编辑不会让旧回执把新地图标成已保存。
- **恢复和最近项目**：刷新恢复，关闭页面后重开恢复最近工程；每标签页记录自身当前工程，避免不同标签页刷新串项目。切换前保护当前已提交数据；浏览器另存为创建具有独立存储 ID 的恢复副本，保留 mapId 和语义数据。它是备份副本，不是生成新 mapId 的布局变体工具。恢复副本有单独列表名称。
- **并发保护**：读取/比较 storageVersion/写入处于同一 IndexedDB readwrite 事务；CAS 失败不覆盖其他标签页。可保留当前恢复副本，或明确放弃当前未保存输入后重载浏览器版本。地图 revision 不参与存储版本递增协议。
- **文件写回增强**：能力检测后显示关联、写回、另存、检查外部变化与重载。用户点击才触发选择器；写入并关闭成功才确认文件摘要。重新聚焦及写前检查原始字节摘要，外部改动不依赖 revision。冲突可重载、保存当前副本、另存，或先保存双方浏览器副本再明确覆盖。再次外改使旧确认 token 失效；非法外部文件保留原件，不能直接覆盖。
- **状态分离**：浏览器草稿、本地文件、导出通知分别显示。JSON 导出不调用持久化确认，也不清除浏览器或文件待保存状态。另有未应用表单输入提示。原单一 savedHash/markExported 已改成内存会话的 acknowledgedHash/acknowledgeMap；目标存储的确认摘要由各适配器独立维护。

详细存储结构见 [持久化契约](M11_PERSISTENCE_CONTRACT.md)。系统文件授权和手工步骤见 [原生文件验收](M11_NATIVE_FILE_ACCEPTANCE.md)。
