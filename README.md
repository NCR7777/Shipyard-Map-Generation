# 船厂拓扑地图绘制器

轻量、本地优先的二维地图绘制与外部系统数据准备工具。节点、道路、设施、区域和服务点保存为可由人及 Codex 直接修改的米制 JSON。地图校验不等于现场运输安全认证，synthetic 示例不代表实测船厂。

调度求解与运行执行属于外部系统。FAST01 在原画布读取外部计划、事件和指标，提供时间条和回放；不建设内置仿真、资源竞争引擎、3D 或 VR。历史 M3A 等报告保留作参考。

## FAST01 操作

1. 打开地图并校准底图，在“描图”选择道路、建筑或区域后连续画。道路自动生成端点和 ID；中间折角只保留为几何锚点。首次在旧图启用新功能时，使用“保留原图并升级”创建 0.3 工作副本。
2. 道路默认宽度 12 m、双向，均标为设计假设；拖动侧柄改宽。C 三点绘弯；绘路中切 R/C 可在同一草稿接续直线和曲线，选择平滑或折角，Enter 完成后一次撤销。默认值调整只影响以后新画的对象。
3. Shift 多选道路后可一次改宽或切换方向；单条道路用“此处开始变宽”拾取位置，自动拆段并只修改所选方向的一侧。M 量距只作米制显示，Enter 结束、Esc 清除，不写地图。同处重复点击或 Tab 循环选择叠放对象。
4. 在“检查与补全”导出 Codex 补标包，将返回的语义补丁导入预览后一次应用；一次撤销可恢复。研究接入仅对勾选目标和明确可通行陆域生成建议。
5. 在“调度结果”先导入 scenario，再导入 A/B 的 plan、events、summary；用时间条、倍率和筛选查看原图上的车辆。下载的 synthetic 包只作文件接入示例。

完整字段、坐标变换、外部版本与示例见 [交换合同](docs/FAST01_EXCHANGE.md)，实际验证见 [FAST01 执行记录](docs/FAST01_EXECUTION.md)。无 DOM 的编译入口：

```powershell
npm run map:compile -- path/to/map.json --out path/to/compiled-map.json
```

## 建筑、区域和入口编辑

顶部“建筑 / 区域”的形状选择提供两点矩形、三点矩形、多边形。三点矩形依次点基边两端，再点侧边确定垂直宽度，可以直接沿斜屋顶描图；多边形逐点画，Enter 或点回起点完成。选中轮廓后可拖顶点；自由多边形可点绿色边中点加点、Alt 点顶点删点。矩形保持四个直角，需自由变形时切换“自由多边形”。

选中建筑，点一次“添加入口”，即可沿高亮外边界连续点击：每次有效点击立即创建一个入口和独立节点，自动命名“入口001、入口002……”；鼠标靠近边界时绿色圆点显示吸附位置。Ctrl+Z 逐个撤销，Enter、Esc 或“完成添加入口”退出，也可在连续模式中直接保存。双击和重复点击已有入口不会重复创建。之后用“道路”从入口节点画出连接。需要自定名称、绑定已有节点或立即接路时，打开“单个入口与接路设置”；“创建时明确接路或到达方式”保留原接路和转向预览。详见[连续添加入口说明与验收](docs/CONTINUOUS_ENTRANCES.md)。

“独立节点”也可先放普通节点。作业点可先放在建筑或区域内，默认用途为“其他”，到达方式留待补充。

建筑、区域、入口和作业点可正常删除，即使地图已有路口、转向或资源。删除含成员的对象时明确勾选成员删除；需要时清理不再使用的节点。资源适用引用按选项维护，容量保留；仍被其他对象引用的入口、私有道路或槽位会显示具体依赖，需显式处理。每次成功删除或边界修改都是一次可撤销事务。 操作范围与真实底图验证见[本次修复验收](docs/SPATIAL_EDITING_FIX.md)。

## 描图透明度

左栏“描图透明度”可分别调整道路带、建筑填充和区域填充的不透明度（0–100%），即时对照底图；0% 只显示边界和中心线，100% 为实色。边界、选中轮廓和编辑控制点保持清晰。默认道路带 100%、建筑与区域各 20%，可用“恢复默认不透明度”单独恢复。

设置随工程保存恢复，不改地图几何、连接、JSON 摘要或撤销历史；绘图草稿中也可调整。“影像对照模式”开启时会在此基础上进一步淡化填充。

## 绘图配置恢复

网格吸附、节点吸附、新建设施/区域类型、快速描图默认值、两种整体移动策略及三个道路显示开关，随 `projectId` 保存在现有 IndexedDB `editorStates` 中。配置变化单独自动保存（600ms 防抖）；“保存工程”或 Ctrl+S 立即保存完整视窗与绘图配置。仅改配置不会修改地图 JSON、revision、摘要或撤销历史。调整视窗后再保存也会保留全部配置。

“恢复绘图默认配置”仅重置这些设置。旧 camera-only 记录自动补默认值；损坏配置提示后仍恢复有效地图，保存失败明确显示未保存。刷新回到选择工具，矩形默认自动识别，不恢复临时自由变形模式、弹窗或未完成输入。字段与失败行为见[保存契约](docs/M11_PERSISTENCE_CONTRACT.md)。

## 道路宽度

已知宽度按米制比例显示道路带，中心线单独绘制；选中不增宽。右侧主要属性区可编辑宽度状态、数值与来源，应用后可撤销、保存和 JSON 往返。未知、不适用、无限制显示辅助虚线；圆端和圆形连接是近似表达，不能当作实测路口或车辆扫掠。旧字段不被自动解释为净宽，详见[宽度口径](docs/M0_DATA_CONTRACT.md#道路宽度的显示口径2026-09-10)。

“显示道路带 / 显示中心线 / 显示普通节点”随工程保存。隐藏普通节点时仍显示选中端点、绘路所需节点和入口/服务点；两个道路显示开关都关闭时隐藏已有道路。分段变宽使用“此处开始变宽”，拾取位置后一次提交拆路和目标半段宽度，继承既有引用并可一次撤销。节点拖动和有效折点草稿同步预览，应用前不写地图。验证与限制见[道路宽度阶段报告](docs/RW01_ROAD_WIDTH_REPORT.md)。

## 节点和道路拓扑编辑

选道路可通过「拆分道路」按里程或画布拾取插入节点；选对象可预览并明确删除依赖。Shift 多选两个节点可合并并选择保留 ID；选二度节点可在兼容条件下「保持道路连通删除节点」。开启「拓扑吸附」后，拖单节点到另一道路中心线或节点，松开后确认连接和所列新增转向；默认关闭，普通坐标吸附不接路。

每次确认一次事务，可撤销、保存和 JSON 往返。坐标框架、锁定及未知语义保护仍生效；不自动合并全图近邻，不删除服务/资源来换取通过。实际范围、操作步骤及十八图验收见 [TE01 交付报告](docs/TE01_COMPLETION.md)。

## 边界直接编辑

单选设施或区域时，从权威边界识别矩形，显示四角控制柄。拖动固定对角，沿自身局部坐标轴独立改变宽高，旋转后的矩形仍保持直角；不默认等比。新尺寸下限为 0.01 m，越过对角时夹至下限。右侧“矩形宽/高”和“固定对角”使用同一算法；宽高为派生值，不另存一套尺寸。鼠标精度受浏览器原生指针事件限制；需要精确的米制宽高时使用数值输入，程序不会隐式吸附或反复舍入 JSON。

不规则多边形及孔洞显示真实顶点控制柄。矩形若需自由变形，先明确选择“自由多边形”；不会按任意四边形猜测矩形，也不会自动删除孔洞或重排原顶点。编辑模式只属于会话，重新导入按实际边界识别。

拖动中仅预览，松开提交一次已有领域事务；Esc、窗口失焦或编辑上下文变化取消预览，非法几何回退并报错。缩放和顶点调整只改边界，不移动入口、服务点或道路节点。整体平移/旋转继续使用原有的关联点策略。保存只包含已提交地图；未应用输入保护继续生效。

## P1 内容支持与 P2A 只读诊断

P1 保留厂界、路口、逻辑资源、已识别槽位的显示、目录定位、类型显隐/锁定和搜索；设施/区域按批准策略做静态内容刚体联动。未知行为继续受保护，完整数据可导出。当前源码、截图、原件 SHA 及实际验收对应见 [本批报告](docs/P2A_COMPLETION.md)。

从底部“检查与问题”入口打开抽屉，在“只读地图诊断 · P2A”中点击运行。检查包含隐藏和锁定对象，清单复用检查器，可点击定位。交点、近邻、重叠和独立子网只是声明候选，不自动接路。所有者包含、槽位正面积重叠及道路带/明确禁区单列覆盖情况；没有声明的条件显示未检查。诊断不会修改地图、revision、撤销历史或资源容量。

选择两个服务点/入口后预览道路方向与转向声明下的路线；视野偏离时点击现有“适应地图”。蓝实线是已声明条件下的路线，橙虚线是含未知条件的候选；各自列出假设。来源服务点沿已有显式出弧离开；到达目标服务点必须走其已声明内部路径。到达声明不自动变成唯一出口。资源占用、车辆扫掠、现实净空及作业完成均不在路径结论内。地图摘要变化后旧清单和路线失效；刷新后手动重新运行。

同核命令（退出 0 仅表示报告生成，不表示无冲突或运输获准；输入无效退出 1，文件/参数错误退出 2）：

    npm run map:diagnose -- path/to/map.json --from servicePoints:SP_001 --to servicePoints:SP_002

真实原件测试默认读取相邻工作区的 projects；独立检出仓库时明确设置其所在根目录：

    $env:SHIPYARD_TEST_DATA_ROOT = '完整数据根目录（内含 projects）'
    npm run test
    npm run test:integration
    npm run test:e2e
    npm run build
    npm run test:production

输入必须匹配冻结 SHA。缺失或被替换会报 blocked_input，不能用简化样例跳过。生产测试默认服务当前 dist；仅 P1 基线取证使用 P1_PRODUCTION_BASELINE=1 和已冻结构建。测试日志、截图和故障副本保存在本地 .cache/P2A，未写回用户原件。

## 大图性能约定（2026-09-24）

- 会话里的地图一律深冻结（`freezeMap`）。`applyMapCommand` 在克隆上执行命令后，把未改动的实体换回输入里的冻结对象，撤销历史因此只多存改动部分。不要原地修改会话地图或其实体。
- 冻结地图的派生结果按对象身份缓存：内容摘要（逐实体规范 JSON）、草稿校验（最近 4 份）、规划读取、道路路径、场景行与目录行。新增派生函数若读取了别的实体，必须把该实体列入 `sceneRow` 的依赖。
- 平移、缩放期间只移动 Konva 舞台变换（`followLive`），不触发 React 渲染；停下或漂移过大时才按新相机重绘。App 只随停下后的相机更新。
- 画布上的地图形状是一个记忆化元素，鼠标移动只重绘草稿、吸附圈等覆盖层；吸附、点选在精确投影前先用路径包围盒剔除远处道路。
- 目录行、问题面板（同码提示 ≥20 条折叠）和隐藏工作区面板都不随每次编辑整体重渲染。按 `?` 查看快捷键与显示约定。

韩华海洋造船厂（620 节点、688 道路、2484 转向，底图 4105×4351），同机先后运行改前、改后构建（Chrome 无头）：画路鼠标移动每帧 258 ms→4 ms，平移每帧 54 ms→8 ms，完成画路最长阻塞 2.3 s→0.37 s，拖动节点提交 1.35 s→0.19 s，边界拖动提交 2.9 s→0.20 s，撤销 0.49 s→0.04 s，导入时长任务合计 4.4 s→1.4 s。编辑一个节点后自动保存的同步计算（Node 同机）由约 1.0 s 降到约 60 ms。
